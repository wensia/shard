## 2. 当前快捷键协议

以下是实际 handler 行为，不是幕布或 XMind 文档的转述。`⌘/Ctrl` 表示 macOS Command 或其他平台 Control。组合输入期间先让输入法处理确认键，不运行结构命令。

| 操作 | 导图选中态 | 导图文字编辑态 | 主编辑区大纲 |
| --- | --- | --- | --- |
| Enter | 当前主题后新建同级；根主题下新建子主题；新主题进入编辑 | 新建同级并继续输入 | 新建同级并把光标移到新主题 |
| Shift+Enter | 在当前主题前新建同级 | 插入主题内换行 | 插入主题内换行 |
| ⌘/Ctrl+Enter | 插入父主题，根主题除外 | 结束文字编辑，保留选中 | 结束当前输入，焦点回到大纲容器 |
| Tab | 新建子主题 | 新建子主题 | 新建子主题；这不是对现有主题缩进 |
| Shift+Tab | 当前主题提升一级 | 当前主题提升一级 | 当前主题提升一级并保留输入焦点 |
| Space / F2 | 编辑当前主题 | Space 为正文输入 | 大纲容器有焦点时进入当前主题；输入框内 Space 为正文 |
| 双击 / 单击 | 双击主题进入编辑；单击只选择 | 原生文字光标操作 | 单击输入框保留鼠标所选光标位置，不全选覆盖 |
| 普通字符 | 用首个字符替换主题并进入编辑 | 原生文字输入 | 输入框内插入；大纲容器没有同等 type-to-edit 分支 |
| ↑ / ↓ | 上一个 / 下一个同级主题 | 原生文字光标 | 仅在全文首/尾且没有选区时转到前/后可见主题，其余由原生光标处理 |
| ← / → | 父主题 / 第一个子主题；→ 先展开折叠主题 | 原生文字光标 | 原生文字光标；没有画布式父子导航 |
| Alt+↑ / ↓ | 同级主题排序 | 原生文字处理 | 同级主题排序，并继续输入 |
| Delete / Backspace | 删除所选主题及其子树 | 空主题才删除主题，普通正文按原生规则删除字符 | 空主题 Backspace 删除；大纲容器选中态也可删主题；根主题受保护 |
| ⌘/Ctrl+Delete | 仅删除所选主题，其子主题上提 | 不作为同一个节点级命令处理 | 无对应专用主题命令 |
| ⌘/Ctrl+/ | 折叠 / 展开当前非根主题 | 无节点级折叠分支 | 无对应快捷键分支，使用折叠控件 |
| Escape | 清除当前选中 / 编辑状态 | 结束编辑，保留选中 | 输入框焦点退到大纲容器，保留选中主题 |
| ⌘/Ctrl+0 | 适应屏幕 | 无对应节点输入命令 | 不适用 |
| ⌘/Ctrl+S | 保存 | 保存 | 保存 |
| ⌘/Ctrl+Z / Shift+Z | 统一工作区撤销 / 重做 | 同一主题连续输入合并历史 | 同一工作区历史；被撤销主题移除时恢复到邻近输入框 |

实现：[导图键盘 handler](../../src/components/shard/mind-map-canvas-editor.tsx)、[大纲键盘 handler](../../src/components/shard/mind-map-outline-editor.tsx)、[工作区快捷键与历史](../../src/components/shard/mind-map-workspace.tsx)。

两个视图可以有不同的文本/结构语义，但同一个可发现入口应明确所处模式。借鉴幕布时不能只改某一处 `Enter` 或 `Tab`，否则会与已经验收的连续录入协议冲突。

## 3. 选择、树结构与移动

| 能力 | 导图编辑 | 主编辑区大纲 |
| --- | --- | --- |
| 单选 | 支持，检查器同步当前主题 | 支持，输入框 focus 只更新选择，不反向全选正文 |
| 多选 | ⌘/Ctrl 点选、Shift 范围选择、空白框选、修饰键追加框选 | 当前组件只接收 `selectedNodeId`，没有主题级多选和批量操作 |
| 拖动 | 多主题成组拖放，目标为之前 / 之后 / 内部；显示拖动预览和目标指示 | 单主题 HTML Drag and Drop，把手拖动，支持之前 / 之后 / 内部 |
| 结构安全 | root 不移动；不能移入自己的后代；父子同时选中时只移动顶层主题 | 复用同一树约束 |
| 排序 / 层级 | 键盘 Alt+↑↓；Tab 新子主题；Shift+Tab 提升；⌘/Ctrl+Enter 插入父主题 | 菜单上移、下移、缩进、反缩进；键盘连续创建和排序 |
| 折叠 | 主题旁折叠控件、快捷键、右键菜单；根主题不折叠 | 有子主题的非根主题显示折叠控件；在折叠主题下新增/缩进时自动展开祖先 |
| 删除与焦点 | 删除子树或仅删节点；删除后选择相邻主题/父主题 | 空主题删除、菜单删除；新建/删除/撤销后恢复可继续输入的位置 |
| 滚动 / 平移 | 普通滚轮平移，⌘/Ctrl+滚轮缩放，Space+拖动画布；WKWebView 专门处理 gesture 事件 | 仅大纲局部 viewport 滚动；新建后显示当前输入框，不滚动 document/window |
| 缩放 / 定位 | 鼠标位置为缩放锚点、适应屏幕；编辑文字时保持缩放，按需平移使主题避开检查器 | 没有导图缩放语义；随可用宽度自动换行 |

结构变更集中在 [mind-map-tree.ts](../../src/lib/mind-map-tree.ts)，布局在 [mind-map-layout.ts](../../src/lib/mind-map-layout.ts)。目前是单根、有序树及自动布局，不是允许任意孤立节点坐标的白板；这种边界应继续保留。

## 4. 文字、样式、备注与引用

- **文字**：节点 `text` 为纯字符串，保留显式换行、连续空行、尾随换行。导图内联输入按实际文字高度补充布局测量；删除文字后自动收缩。大纲每一行是独立、自动增高的 textarea，随宽度及字体加载重新测量。预览卡片仍可截断，完整编辑器不按预览行数截断。
- **样式**：节点支持默认、陶土、青绿、琥珀四种强调色和自动/预设宽度；绘制与控件消费 Kiln token、沿用 Noto Sans SC。没有逐字富文本、粗体/斜体/高亮区间、图片、图标库或主题皮肤编辑器。
- **备注**：`ShardMapNode.note?: string` 已存在于 TS/Rust 模型，并在结构变更中保留；当前检查器和两个编辑视图均未提供备注编辑/阅读入口。添加纯文本备注可沿用现有字段，但需要新的可发现入口及保存/重开验收。
- **引用**：检查器可搜索并添加其他导图、流程图、公开文档/片段；重复目标去重，当前导图自身从候选中过滤。支持移除引用、打开引用；打开前保存，保存失败留在当前文档。引用以目标 ID 存储，标题为展示查询结果，不复制目标内容。
- **现有局限**：备注、链接、强调色在主大纲内缺少可见提示；链接主要依赖检查器发现。主大纲没有富文本工具条、完成状态、子树聚焦、全文搜索、主题级复制粘贴/批量文本转树或导图导出入口。不要把节点原生文本复制粘贴等同于复制主题结构。

源码：[输入测量](../../src/lib/mind-map-text-metrics.ts)、[导图输入与渲染](../../src/components/shard/mind-map-canvas-editor.tsx)、[大纲自动高度](../../src/components/shard/mind-map-outline-editor.tsx)、[检查器](../../src/components/shard/mind-map-document-inspector.tsx)、[文件类型](../../src/types.ts)。

## 5. 保存、历史与文件安全

- `MindMapCanvas` 统一管理读取结果、草稿、选择、保存、冲突和历史；两个编辑器只提交新的树及变更合并键。连续文字输入按主题合并撤销历史，结构动作单独入栈，历史有上限。
- 自动保存去抖后执行，组合输入期间不写；有保存进行时等待前一个请求，再持续排空保存期间新增的草稿。旧保存返回结果仅在草稿没有继续变化时回填。
- 保存失败保留草稿并展示状态；不会静默无限重试，后续编辑或手动保存可恢复。冲突展示「保留我的版本」和「保留磁盘版本」。引用导航和资料库切换使用异步保存门禁。
- Rust 在后台 `run_blocking` 处理文件 I/O，内容写入拿 vault gate；验证 revision + hash，冲突先落独立副本；有效内容原子落盘并维护 last-good 备份。正文写入没有内嵌 Git commit。
- 主视图、检查器开关、导图临时平移缩放和大纲滚动目前是组件状态。切换主视图会卸载子编辑器；`ShardMapFile.viewport` 虽已建模，但当前导图组件没有读取/写回它。不能宣称已实现跨视图/重开视口恢复。

源码：[工作区保存控制](../../src/components/shard/mind-map-workspace.tsx)、[树内容比较](../../src/lib/mind-map-tree.ts)、[Rust create/read/write/validate](../../src-tauri/src/lib.rs)、[资料库导航](../../src/workspace/library-shell.tsx)。

## 6. 数据模型扩展风险

| 变更类型 | 风险与必要边界 |
| --- | --- |
| 增加快捷键提示、视图标签、菜单分组 | 不需要改文件 schema；需确认真实键位、文本编辑态、IME 和窄窗口，不展示尚未实现的命令。 |
| 显示/编辑现有 `note` | TS/Rust 均已有字段，可复用统一草稿和 mergeKey；验证重排/复制/删除/撤销后字段完整，以及空备注策略。 |
| 记忆本次打开期间视口 | 优先用工作区临时状态；不要把每次平移写入内容历史或触发保存。跨重开持久化需另定视图状态与内容状态边界。 |
| 增加完成状态、富文本、图标、布局方向等字段 | Rust 文件、节点及样式均 `deny_unknown_fields`；只改 TS 会导致原生读/写失败。需要同步 serde、schema 兼容策略、验证器、复制/比较、迁移和读写测试。 |
| 引用从文档细化到主题 | 当前链接只有文档目标，没有 node anchor；需处理节点移动、删除、目标不存在与引用回退，不应把临时 DOM ID 当持久化协议。 |
| 富文本替换 textarea | 会影响光标、中文组合输入、粘贴、换行、撤销合并和 SVG 字宽测量，不宜作为一次 UI polish 顺手替换。 |
| 大纲主题多选/批处理 | 当前大纲只有单选回调；可复用树批量移动的约束，但还需定义文本选区与主题选区的区分，不能只给行添加选中样式。 |
| 大文件能力 | 当前会遍历整树、克隆文件、按全部可见主题渲染；`getMindMapChildren` 反复过滤整份节点表，大纲引导线也向后扫描。未找到千级主题实际性能验收；不能据小树测试宣称大型大纲流畅。 |

当前 Rust 校验包括单根可达树、无循环、同级 `sortKey` 唯一、节点/文字数量上限、有效宽度、公开文档引用边界。增加特性应在这套约束上推进。

## 8. 借鉴幕布时优先考虑的少量改进

1. **先让当前能力容易找到**：明确主区「大纲 / 导图」切换，区分检查器「大纲导航」；提供与当前模式匹配的快捷键入口，补充上下文菜单中的快捷键提示。复用现有处理函数和 Kiln 控件即可，不需要 schema 变更。
2. **减少切换后的方向丢失**：保留本次打开期间的导图缩放/平移、大纲滚动及选中主题；切换视图定位同一主题。先定义临时视图状态，避免与内容保存/撤销混在一起。
3. **使正文与补充信息有层次**：若幕布实测支持该方向，可用已有 `note` 增加可折叠的主题备注，并让大纲能看到关联文档提示。主文字仍保留已验证的输入行为。

上述是源码支持的候选项，实施取舍应结合真实幕布观察。完成状态、富文本、图片、布局主题、跨文档节点锚点、导入导出和协作属于后续独立功能，不应为了「看起来完整」一次加入。
