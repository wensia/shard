# 资料库文件标题重命名验收

日期：2026-09-08。

资料库内的笔记、思维导图、多维表格、流程图和旧画布统一通过顶部文件名进入重命名。复用已有输入框：点击后全选名称，Enter 或失焦提交，Esc 取消；中文选字的 Enter 不提交。

标题输入框默认固定为 240px，窄处允许收缩，不随文件名长度或标题栏剩余空间扩张。长名称在单行输入框内随光标横向滚动。Chromium / WebKit 已验证短名称与长名称宽度一致、首尾光标对应可见文字变化及 640px 布局；原生验收窗口也已查看滚动到名称首尾的效果，测试输入通过 Esc 取消。

标题栏进一步拆为稳定的返回区、可收缩的标题区和独立操作区；文字与输入框仅在标题区内切换。返回按钮在改名时持续保留，保存状态与禅模式按钮由操作区定位，不再依赖标题文字填满剩余空间。Chromium / WebKit 对比 1280px / 640px 下编辑前、长名称输入、取消和提交后的按钮矩形，位置均保持一致；原生窗口也已对比默认、编辑、取消三个状态。此轮 8 项相关 UI 回归、构建与差异检查通过。

失焦关闭补充：Tauri 的标题栏拖动处理会取消 `mousedown` 默认焦点转移，原生窗口中点击标题栏空白因此不会触发输入框原有的 `onBlur`。现在仅在标题编辑期间捕获外部 `pointerdown` 并主动失焦，窗口失活时也结束输入焦点，继续使用统一提交逻辑。输入框内部点击保留编辑；未改名称直接关闭，修改名称自动保存，失败则保留草稿供修正。改名请求合并等待，返回按钮在同一次点击中等待保存与改名完成；快速失败也不会误跳离工作区。

本轮 9 项 Chromium 相关回归和 2 项 WebKit 外点回归通过，覆盖标题栏拖动的焦点行为、画布空白、Tab、禅模式、慢保存后返回以及按下返回后快速报错再松开的时序。`pnpm build` 与 `git diff --check` 通过。隔离原生窗口已复现修复前问题，并验证修复后空白点击关闭、外点自动改名和一次点击返回；测试名“失焦关闭验收”已恢复原名，文件内容 SHA-256 与下述原生验收基线一致。

本次补齐思维导图入口，并将目录刷新与选中文件路径更新放在同一个同步回调中，避免改名成功后查看器被缺失文件检查清空。结构操作继续先排空草稿，再调用已有异步重命名命令；保存期间标题输入禁用并标记 busy。重命名不修改 Markdown 正文、图文档内部标题或根主题。

## 验证结果

- 新增 3 项用例在 Chromium / WebKit 各通过一次：确认、失焦、取消、同名不提交、IME、扩展名、保存顺序、保存失败、名称冲突、修正重试、改名后继续编辑并按新路径重开。
- 已有 4 项 Chromium 回归通过：普通导图打开、笔记重命名、表格改名期间冻结与恢复、流程图改名移动后稳定 ID 链接。
- 标题与输入框计算样式符合现有 Kiln token，640px 下输入框不越界。[Chromium 输入态](../../tests/evidence/title-rename/chromium-input-640.png)、[WebKit 改名后](../../tests/evidence/title-rename/webkit-renamed-640.png)。
- `pnpm build`、`git diff --check` 通过，保留现有大包提示。
- 在既有 `Shard Multidrag Acceptance` 原生窗口、已核对的隔离测试资料库中，点击导图标题，改名为“标题点击重命名验收”，核对新文件存在且旧路径消失，再通过同一入口恢复原名。标题和查看器保持正常，改名前后及还原后的文件 SHA-256 均为 `c1172a5a8d9bb9d76b4c05d2718397702b220b0e37454ee3153ecf5c7206a3c9`。原生只执行改名与恢复，没有修改正文。

图片是内容寻址附件，CSV 当前由系统应用打开；它们没有此次复用的应用内文档标题栏，未更改附件路径规则或新增 CSV 查看器。
