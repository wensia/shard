# Shard：只围绕碎片的产品设计

日期：2026-09-15。状态：设计方案，代码尚未实施。

本轮交付产品边界、交互规则、存储与 Agent 接入契约、模块退役及验收计划。未删除应用模块、修改运行配置、扫描或迁移用户数据，也未执行任何远端同步。后续实施以阶段验收为准，不能把本文件中的目标能力描述为已经可用。

配套文档：[存储、同步与 Agent 接口](fragment-storage-sync.md)、[模块退役与数据迁移](fragment-only-migration.md)。

本版已根据一轮 Grok 审计和源码事实复核修订，原始意见及逐项处置见 [审计记录](fragment-only-grok-audit.md)。这是文档修订状态，不表示实现或外部链路已验收。

## 1. 产品定义与决策

**Shard 是一个本地优先的碎片记录工具。桌面用于记录、查找和整理；移动端通过已有聊天软件与 Hermes / OpenClaw 交互。**

产品只维护一种正式内容对象：碎片。正文可以很短，也可以较长；内容变长、添加标题或被 AI 整理，都不会使其变成另一种产品对象。

用户明确要求 Git、飞书、夸克网盘和本地离线可组合配置。本方案将“保存在哪里”与“从哪里操作”分开：远端连接负责同步或备份，Agent 负责调用碎片操作。飞书聊天不强制搭配飞书存储，使用 Hermes 也不强制关闭 OpenClaw。

| 决策 | 本方案的选择 |
| --- | --- |
| 内容边界 | 只有碎片、碎片附件、碎片之间的关系与回收站状态 |
| 私密碎片 | 用户已明确保留；隐私是碎片属性，取消独立密匣工作台，沿用已有加密与解锁机制 |
| 本地能力 | 始终保留完整本地保存；新库不依赖 Git、云账号或 Agent 才能使用 |
| 远端目标 | Git、飞书、夸克均可独立启停，可同时保存副本 |
| 首版同步拓扑 | 每个碎片库至多一个主要双向通道，其余连接做备份；全关即纯离线 |
| 推荐组合 | 用户主动选择飞书双向同步、Git 版本备份、夸克定时备份；不是自动启用配置 |
| 已有用户 | 保持原数据目录、Git remote、自动同步开关；不因升级自动上传至新平台 |
| Agent | Hermes、OpenClaw 共用确定性的碎片工具契约和数据格式 |
| 手机端 | 不开发独立 Shard 手机 App；聊天承担捕捉、查找和明确的修改操作 |
| 非碎片模块 | 移除产品入口与专属实现；旧数据通过独立迁移流程保留，不自动销毁 |

“双向同步”表示不同 Shard 节点可以通过该目标交换变更，不等于远端任意文件或表格编辑都能安全写回。飞书首版由工具写入不可变修订记录，当前碎片表供查看；直接修改表格正文暂不作为正式编辑入口。这样避免依赖尚未确认的远端条件更新能力。“不可变”是 Shard 协议约束，飞书本身仍可能允许人工修改或删除，读取时必须检查完整性，不能将损坏记录报告为同步完成。

## 2. 保留、移除与兼容边界

| 能力 | 决策 | 产品行为 |
| --- | --- | --- |
| 快速记录、Markdown 编辑、时间线 | 保留 | 默认启动即可记录，保存不等待网络 |
| 搜索、标签、日期与置顶筛选 | 保留 | 按需展开，所有结果都定位到同一碎片流 |
| 图片与普通文件附件 | 普通碎片保留并统一归属 | 从所属碎片上传、查看、下载和导出；不提供独立文件管理工作台；私密附件限制见下文 |
| 普通 Markdown 表格、列表、代码块 | 保留内容兼容 | 复用已有源码编辑和渲染，不新增数据库网格编辑器 |
| 碎片关联、反链、相关碎片 | 保留 | 以列表和引用呈现，不使用全库图谱或画布 |
| 多选、批量标签、回收站、导出 | 保留 | 只操作明确选中的碎片；导出正文与附件 |
| AI 整理 | 收敛为碎片动作 | 预览结果，用户保存后创建新碎片并保留来源；默认不覆盖原文 |
| 思维导图、流程图、自由画布 | 导图与流程图改为内容类型（2026-09-28 修订），自由画布移除 | 大纲（导图是其视图）与流程图各是一篇 md，正文是唯一受管 JSON 区域，进入时间线，不恢复独立工作台；碎片正文仍可内嵌 ```mindmap 围栏块；见 [产品框架](product-framework.md) §2、§2.1 |
| Shard 内置多维表格、CSV/XLSX 工作台 | 移除 | 不再创建或编辑原生表格对象；旧格式保留与导出 |
| 资料库、目录树、文档空间 | 移除 | 不再有“转为文档”或“保存到资料库”生命周期 |
| 独立回顾、洞察、漫步工作台 | 移除独立空间 | 必要的相关碎片发现可保留在碎片上下文；不新增专题工作台 |
| 私密碎片 | 保留日常创建、读写与安全边界 | 复用碎片流和编辑器，按隐私状态解锁访问；移除独立密匣工作台，不删除加密实现 |
| 飞书多维表格连接 | 保留为存储适配器 | 外部保存方式，不恢复 Shard 内置多维表格产品 |

长文仍是碎片。AI 整理结果仍是碎片。附件不因是 CSV、PDF 或 Markdown 文件就自动导入成新的内容类型。

旧链接指向退役对象时保留原链接文本及目标身份，展示“旧格式内容”；可以定位保留文件或进入导出流程，不静默改为指向无关碎片。批量转换旧内容必须提供预览、来源与损失说明。

## 3. 主界面与日常操作

### 3.1 结构

```text
左侧导航                  主内容区
搜索                      固定的碎片输入框
全部碎片                  -----------------------
私密碎片（需解锁）
标签（可展开）            碎片时间线 / 当前筛选结果
                          仅该 viewport 纵向滚动
回收站
------------------        按需出现的多选操作栏
本地 / 同步状态
设置
```

不保留“空间切换器”，不按存储服务创建内容分区。置顶、日期和来源属于筛选条件，不再新增一级导航。“私密碎片”是同一碎片流的门控状态，不另建工作台或内容类型。首页默认不常驻整排筛选按钮；从搜索和标签按需进入条件视图，只有条件生效后显示摘要与清除动作。

时间线延续已有卡片、置顶和渐进渲染能力，不以固定条数截断全部碎片。选中碎片可进入专注编辑，保存后回到原位置，不演变为多标签文档工作台。

### 3.2 核心交互

| 场景 | 完成行为 | 失败或边界 |
| --- | --- | --- |
| 创建碎片 | 本地持久化成功后加入时间线，后台按连接配置投递 | 本地失败保留输入；网络失败不撤回已保存碎片 |
| 修改正文 | 本地保存后显示保存结果，后续投递新修订 | 保存失败保留草稿；导航不能吞掉修改 |
| 筛选中创建 | 使用用户输入的正文和标签，不隐式继承筛选条件 | 不匹配当前筛选时提示已保存并提供定位入口 |
| 搜索或关联跳转 | 仅滚动时间线 viewport，返回恢复先前范围与阅读位置 | 目标在回收站时说明状态，不自动恢复 |
| 多选 | 从卡片菜单进入；展示所选数量与作用范围 | 切换筛选前清除选择，避免操作不可见对象 |
| AI 整理 | 首版仅处理普通碎片；来源只读，生成结果可预览、修改；点击保存后成为新碎片 | 私密来源不发送给 AI；失败保留选择和输入；生成成功不等于已经保存 |
| 删除与恢复 | 进入或离开碎片回收站，并形成可同步的修订 | 删除与离线修改冲突时保留可找回版本，不静默复活 |
| 导出 | 输出选定碎片、必要元数据和归属附件，可离线阅读 | 不把未下载附件或缺失文件报告为完整导出 |

Composer 始终是固定交互区。程序化定位由时间线标记，不能触发输入框折叠；不得使用 document/window 滚动定位或全局 `scrollIntoView()`。

### 3.3 私密碎片

用户已明确选择“保留私密碎片能力，取消独立密匣工作台”。保留已有加密格式、密钥管理、解锁和空闲自动上锁机制，沿用原有安全写入路径；本次不重写密码学实现。

- 捕捉区保留明确的普通/私密保存目的地。新库默认普通，已有用户保持原有目的地设置；筛选条件不会隐式改变新记录的隐私属性。
- 在私密阅读范围中，若目的地仍为普通，提交前提供本次保存的可见确认，说明将进入普通碎片及其连接；未确认不写普通文件或出站项。用户主动切换为私密仍按私密保存，确认不改变全局默认。
- 沿用现有已配置写入公钥时的锁定投递能力；新建私密碎片不强迫打开私密阅读范围，读取、搜索和编辑仍需解锁。缺少写入密钥时沿用首次解锁流程，锁定回执不展示私密摘要。
- 点击“私密碎片”先解锁，再使用相同的时间线、编辑器、搜索和回收站能力。私密/普通数据在界面与索引中始终有明确边界，不能只用隐藏 CSS 处理。
- 首版保留现有私密碎片不支持图片附件的限制，也不向私密模式新增普通文件附件。隐藏或禁用未支持入口，工具端同步拒绝；带附件的普通碎片转私密时明确阻止并保留原件，不把附件继续留在公开 `assets/` 中却显示为已加密。
- 现有图片检查仅覆盖部分写法，统一入口必须补齐行内、引用式及 HTML 图片和本地附件引用校验；私密渲染不自动加载外部图片或生成远端预览。这里是实施验收要求，不能视为现有拦截已经完备。
- “全部碎片”和默认搜索表示普通碎片范围；私密正文、标签、摘要、附件及关联预览不混入。私密搜索只在解锁后的私密范围内执行。
- 离开私密范围、手动锁定及既有空闲上锁条件触发后，清除解密内容和搜索状态。不能因为页面不再叫 lockbox 就取消原有上锁逻辑。
- 新增云连接和 Agent 默认只处理普通碎片。已有 Git 对密文的保存语义保持原样；新目标的私密同步需通过密文传输和密钥交付验证后才允许启用，绝不自动解密上传。
- 私密来源的摘录、派生碎片及关联说明继承私密属性，不能因“另存为新碎片”回到普通默认。首版私密视图不开放云端 AI 整理，也不把私密来源交给 Agent；本地派生产物要公开时须另行预览明文及接收目标并明确选择公开。
- 普通碎片转为私密仍是明确操作，并说明已有远端副本和 Git 历史不会因此自动消失；本次不重写历史。导出私密正文为明文时必须由用户明确选择目标与范围。
- 转换预览逐目标列出未发送、结果未知、已存在的明文修订/快照及核对时间，特别标明飞书修订中的旧正文。暂停目标或另建目标不会撤回旧副本，转换后不能显示“全部副本已保护”。
- 转私密同时停止尚未发送的普通修订出站，核对传输中的结果；晚到的普通修订不能自动放回公开流。若待推送 Git 提交已包含旧明文，暂停该目标并说明历史范围，不能继续推送后声称已保护全部副本。协议细节见存储方案。

### 3.4 本地与远端状态

“已保存”只表示当前节点可靠保存了该修订。每个目标分别记录待处理、进行中、已完成、失败、授权失效、暂停及冲突状态。

默认主界面以低干扰状态显示本地保存；需要处理的失败或冲突才提升可见性。点击同一个状态入口查看目标详情，例如“飞书已同步，Git 待推送，夸克下次备份尚未到期”。未到计划时间不算失败，已经 Git commit 不等于已经 push。

恢复联网后自动续传，避免要求用户反复点击。全部目标失败时仍能记录；主通道续传缺失修订，备份执行节点继续未完成的检查点或快照，不重新制造正文变更。非备份节点显示“等待指定节点备份”或最后已知覆盖范围，不显示虚假的本机 Git 待推送。

## 4. 设置页

沿用现有分栏设置壳层，使用“本地数据 / 同步与备份 / Agent 接入 / 外观与快捷键”四组。同步凭据、队列、历史结果不进入主内容导航。

### 4.1 本地数据

- 显示当前碎片库名称、数据目录、已下载附件占用与最近一次本地备份结果。
- 默认正文及附件完整保留在本机；若用户改为附件按需下载，明确未下载附件无法离线查看。
- 更换目录先识别现有库，预览“打开已有库”或“迁移当前库”，禁止静默替换库身份。
- 提供碎片导入、完整导出、备份恢复与旧格式数据处理入口；这些是维护流程，不是资料库工作台。

### 4.2 同步与备份

一个连接列表承载 Git、飞书和夸克。每行呈现用途、目标位置、启用状态、上次成功时间和待处理数量，详情按需展开。列表只有一个统一“立即同步”动作；单行失败提供明确的“重试该连接”。

| 配置 | Git | 飞书 | 夸克 |
| --- | --- | --- | --- |
| 目标 | 仓库地址、分支 | 账号、同一连接下的修订存储与当前碎片查看表 | 账号、备份目录 |
| 模式 | 主要双向通道 / 版本备份 | 主要双向通道 / 备份 | 备份与恢复；双向模式待专项验证 |
| 自动执行 | 开关、频率 | 开关、频率 | 开关、备份频率与保留策略 |
| 执行节点 | 备份模式指定一个写入节点 | 主同步指定一个当前表更新节点；备份指定一个快照节点 | 指定一个备份节点 |
| 状态 | 本地提交与远端完成分开 | 修订保存与当前表更新分开 | 本次完整备份与部分上传分开 |
| 调整 | 编辑目标、暂停、凭据管理、断开 | 编辑目标、暂停、重新授权、断开 | 编辑目录、暂停、重新授权、断开 |

新连接的默认集合是同一库的普通碎片、关系、回收站状态与归属附件；排除未迁移的资料库、导图、私密碎片和无归属文件。备份以所选范围的可恢复集合为单位，回执明确范围，不允许仅复制正文却显示“完整备份”。

单机使用时执行节点默认是本机；多节点使用时在连接详情显示实际执行节点，允许迁移给常驻节点。备份节点离线时保留待处理状态，不由其他设备自行接管同一分支或查看表；切换执行节点前核对旧任务与新节点基线，避免两个节点同时改写派生数据。

主通道按操作出站；备份由指定节点在应用本地或远端修订后生成检查点/快照。飞书备份保存可恢复的完整快照，可附查看投影，但不将表内修改导入库，不作为第二个主通道。切换写入节点须确认原角色停止；主通道切换须原写入节点均确认暂停。节点失联或写入结果未知时保留切换未完成及本地记录能力，不自动接管。

已有 Git 仓库继续包含原有历史，既有或待推送提交可能含旧模块文件与密文；只缩小未来纳管目录无法排除这些历史对象。若用户要求旧数据不进入一个新 Git 目的地，必须在预览后创建独立的纯碎片仓库，不能直接换旧 origin 或静默重写历史。

飞书的当前表明确标为派生查看视图。发现人工改表时暂停该投影刷新，保留所见差异并提示重新生成或显式导入；不得在下次同步时无提示抹掉用户修改。修订记录被改写、删除或校验失败时保留本地内容并报告异常，不能让投影“看起来最新”代替实际完整性校验。

至多一个主要双向通道是首版产品边界，不影响同时启用多个保存目标。用户修改主要通道时执行迁移流程：先保存待处理状态，比较新旧库身份与修订，展示计划，完成基线核对后切换。旧通道保留为暂停连接或明确选择的备份，不自动串联成多个写入源。

### 4.3 配置生命周期

| 动作 | 预期行为 |
| --- | --- |
| 首次连接 | 验证身份与目标权限；只读检查现有内容；展示首次上传/接入计划；用户执行“启用”后开始 |
| 测试连接 | 只读检查；若需要真实写入测试，明确目标、测试对象和清理方式，不能把读成功当写成功 |
| 暂停 | 停止新的远端任务，保留待处理进度与两侧内容 |
| 断开 | 停止投递并解除连接绑定，保留本地和远端数据；不自动注销其他程序共用的 CLI 身份 |
| 更换账号或目标 | 视为新目的地，重新预览；不携带旧游标盲目覆盖新目标 |
| 修改连接配置 | 操作期间局部 busy，保留输入；成功后在原设置页展示结果 |
| 从备份恢复 | 默认恢复到新目录，先检查清单/附件/版本完整性，再预览合并；不直接覆盖当前库 |
| 清理历史备份 | 仅处理明确保留策略覆盖的备份集合；保留可用恢复点，不与回收站清空混用 |

连接配置按碎片库绑定，设备认证和本机目录按节点保存。原始密码、明文主密钥、恢复口令与云连接凭证不进入 Markdown、Git、飞书正文或夸克备份；不同节点独立认证。既有 `.shard/lockbox.json` 中加密封装的恢复元数据按原有密文保存和恢复规则保留，不能被通用“排除凭证”规则误删。配置面板不显示原始响应、token 或内部日志作为日常内容。

### 4.4 Agent 接入

Hermes 与 OpenClaw 可以同时连接同一个库，各自有连接身份与操作权限。初始提供创建、搜索、读取；修改、回收站操作和批量动作按用户授予的范围启用。接入层执行权限校验，Skill 只解释怎么调用，不能承担安全门禁。

设置展示连接名称、实际运行节点、执行身份与隔离验证状态、可执行操作、默认记录行为、最近一次调用结果与断开入口。平台消息发送者必须映射到固定库与授权主体，不能由模型自由传入任意库路径或任意飞书表格标识。阶段 C 必须验证 Agent 的 shell 无法绕开工具直接读写受限数据或凭据；仅换成同系统账号的另一个进程不足以兑现权限限制。

支持两种会话习惯：专用碎片会话里普通文字默认记录；通用 Agent 会话里“记一下”等明确记录意图才触发创建。查询结果、摘要和普通闲聊不会自动成为碎片。

## 5. Agent 体验与部署边界

| 用户输入 | 工具行为 | 回执 |
| --- | --- | --- |
| “记一下：减少用户做决定的次数。#产品” | 保存原话与明确标签，记录来源身份 | 当前节点保存成功及所选远端的真实状态 |
| “找找我之前关于定价的想法” | 检索正式碎片库，返回可定位的原文与 ID | 未找到时说明范围，不用会话记忆伪造碎片 |
| “给刚才那条加创业标签” | 依据前一条回执的稳定 ID 修改 | 指代不明确时澄清对象，不猜测覆盖 |
| “整理一下本周的产品想法” | 读取实际来源，生成有引用的整理结果 | 默认仅展示，用户要求保存时创建新碎片 |
| “删除刚才那条” | 在权限和对象明确时移入回收站 | 说明已移入回收站，保留恢复入口 |

保留同一条来源消息的幂等身份，重复投递或两个 Agent 重试不能重复创建。可信来源键缺失时工具拒绝写入，不由模型补随机键；两个 Agent 共同调用一个消息写入服务，采用相同平台原始消息身份及已登记动作计划，同键异动作返回冲突。分别部署时也不允许各自离线执行同一聊天消息；写入服务不可达时明确待处理或未保存。结果使用已持久化的操作回执，不能凭自然语言“我记住了”宣称保存。

两种部署形态使用同一套内核与工具契约：

| 形态 | 运行位置 | 能力边界 |
| --- | --- | --- |
| 本机模式 | Agent 和 Shard 数据都在 Mac | 离线记录可用；Mac 关机时不能即时处理聊天 |
| 常驻节点模式 | 已有 Agent 服务器上运行轻量无界面碎片节点 | 节点有自己的持久化目录，电脑关机也能接收；桌面上线后经共享通道同步 |

常驻节点不是新增文档管理产品，也不要求首次使用就部署服务器。V1 通过已启用的 Git 或飞书主要通道连接桌面与节点。若只启用夸克备份，节点能保存；只有它同时承担备份角色且上传完成时才能确认已备份。指定关机桌面备份时只能显示尚未备份，不能假定桌面持有节点新内容；桌面仍须恢复/导入，不能显示“已自动同步到桌面”。后续节点直连协议或经过验证的夸克同步可补齐这一组合，具体门禁见配套存储方案。

## 6. 数据与实现约束

正式业务数据包括碎片 ID、正文、创建/修改时间、标签、置顶、隐私状态、附件、关联、删除/恢复状态和修订关系。私密正文及敏感元数据继续位于既有加密封装中，不能因增加统一模型而另存明文副本。同步目标 ID、远端记录 ID、重试信息及账号凭据是连接状态，不能反向决定碎片身份。

正文继续以 Markdown 文件保存。额外的持久化变更记录保留安全重试和恢复需要的信息，搜索索引可重建；文件写入与待处理记录的崩溃恢复顺序必须明确。具体数据格式与并发规则集中在 [存储方案](fragment-storage-sync.md)，本文件不另建一份协议。

复用现有 React/Tauri/Markdown 编辑能力，先抽出碎片写入与同步边界；不随模块退役升级框架、换编辑器、引入新的全局状态库或重做设计系统。共享 Markdown 包的其他消费者不在本次移除范围内。

所有文件操作、Git、网络、CLI 进程、索引与大正文解析走后台任务。捕捉保存不等待远端任务；受影响控件提供局部 loading / disabled / aria-busy。实际修改写入策略时必须同步核对项目 AGENTS.md，不沿用旧方案中的逐条内嵌 Git 提交。

### 6.1 视觉与可访问交互

- 沿用 [Kiln](../../vendor/kiln/SKILL.md) 的桌面编辑壳层和标准设置密度，不增加装饰性大卡片或独立集成仪表盘。
- 主字体使用本地打包的 Noto Sans SC，消费现有字体 token；断网冷启动不依赖 CDN 才能正常排版。
- 消费 `--background`、`--card`、`--foreground`、`--muted-foreground`、`--primary`、`--success`、`--info`、`--warning` 与 `--destructive`，间距、控件和表面圆角复用 Kiln token，不另写原始值。
- 主动作、普通动作、低频元信息保持三层；一个视图只有一个主要动作。控件使用项目共享组件，hover/busy 不改变尺寸。
- 保持 Shard 的 managed-navigation 焦点策略：Tab 归编辑器，F6 切换工作区域，指针操作后不画焦点框；保留鼠标输入、程序化焦点恢复、中文输入法与业务选中状态。
- 设置内容区内部滚动，头尾操作保持可见；窄窗和短窗口保留退出及保存入口，不让列表数量撑大对话框。

## 7. 实施与验收

本轮只完成文档。后续以 [迁移计划](fragment-only-migration.md) 的阶段和 [存储方案](fragment-storage-sync.md) 的能力门禁执行，阶段不能用“按钮已出现”代替链路验收。

第一份可交付实现应先证明碎片产品收敛和本地数据安全，再加入连接与 Agent。Git、飞书、夸克备份及两种 Agent 都属于目标方案；夸克双向、节点直连和飞书直接改表属于明确未开放的后续能力，不显示为已支持模式。

| 验收面 | 必须获得的证据 |
| --- | --- |
| 产品收敛 | 导航、菜单、快捷键、搜索、后台加载、Tauri 命令中无退役产品入口；旧路由安全回到碎片；私密命令仅服务保留的碎片能力 |
| 本地离线 | 冷启动断网后创建、编辑、搜索、回收站和已下载附件可用；退出重启后内容仍在 |
| 多目标 | 同时启用主要通道和两个备份目标，一个失败不阻塞本地或其他目标；逐目标读回验证 |
| 并发与重试 | 同一消息重复投递、离线两端修改、删除对编辑、同步途中退出均不丢内容或重复创建 |
| 移动链路 | 实际 Hermes 与 OpenClaw 各完成聊天到存储再到桌面的读回；常驻模式下关闭 Mac 重做 |
| 附件与恢复 | 另一节点完整显示附件；从实际备份重建碎片、关系、回收站与附件并核对清单 |
| UI | 默认/hover/busy/error、明暗主题、正常/窄/短视口，composer 与定位几何及真实计算样式 |
| 旧数据 | 原始资料、密文、共享附件、链接和 Git 历史可找回；无静默转换或清空 |
| 私密能力 | 日常创建/编辑/恢复可用；离开与空闲仍上锁；公开搜索、日志、新连接、Agent 均无明文泄漏 |

纯文档阶段检查差异、相对链接和规则一致性。代码阶段运行相关单元测试、`pnpm build`、`cargo check`、`git diff --check` 与适用 `pnpm test:ui`；原生 Tauri 验收和真实平台同步分别记录。
