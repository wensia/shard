## 偏差

1. 施工令要求转换路径使用 `apply_frontmatter + render_fragment`，但源码已有 `conversion_title_keeps_exact_body_identity_metadata_and_original_month`，明确要求转换时保留 closing fence 后的正文边界、尾随空格与尾随空行；`render_fragment` 会执行 `trim_end`，两者冲突。按“业务语义与正文 trim 规则不变”及源码事实，转换路径使用 `apply_frontmatter` 更新 raw，再沿用原有精确正文拼接；其他普通更新路径使用 `write_fragment_update`。
2. `update_fragment` 与 `update_fragment_tags` 是依赖 `AppHandle`、Tauri State 的异步命令，现有测试设施不能直接构造该命令环境。为覆盖命令实际使用的写入逻辑，最小提取 `update_public_fragment_in_vault` 与 `update_public_fragment_tags_in_vault` 两个私有同步 helper，命令与集成测试共用，命令签名和外部行为不变。
3. 施工令按“第 0 列非空行开始顶层条目”描述切片，但当前 `serde_yaml 0.9` 对 `Vec` 的规范输出是第 0 列 `- item`；若把这些行视为新条目，会在第二次更新时留下旧列表并破坏字节一致性。实现将第 0 列 `-` 视为前一个映射键的值续行，其余无法识别的第 0 列内容仍是不透明条目。
4. 施工令文字中的两个公开转密匣入口在源码中是并列 wrapper，并非串行调用；同时 `related` 原先只在 `write_lockbox_fragment_file` 重建投影时隐式清空。实现按真实调用链让两个入口都传递 raw，并在共同 payload helper 中显式清空 `related`，从而让加密载荷与锁定态返回投影一致。
