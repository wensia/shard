# Z2 真实应用冒烟缺陷修复报告

## 缺陷一：筛选对话框关闭后下拉弹层残留

**根因与调用链。** `FragmentFilterDialog` 连续使用类型、属性名、属性运算三个 `SelectControl` 后，控件的 `open` 虽已变为 `false`，`src/components/ui/select.tsx` 却始终渲染 `Select.Portal`。Base UI 关闭过渡期间，三个 `Positioner/Popup` 仍挂在对话框外的 portal 中；Chromium 复现时可数到 3 组节点，紧接着按 Esc 会被已关闭的 Popup 键盘处理拦住，对话框保持打开。原生 WKWebView 冒烟报告记录了这些弹层在对话框关闭后仍可见并遮挡资料库；自动化 WebKit 没有复现该持续可见状态，因此不把具体过渡事件是否丢失写作已证实原因。

**修复。** 共享 `SelectControl` 只在 `open && !disabled` 时渲染 portal，关闭时立即卸载弹层；无需改变筛选对话框、视觉样式或选择值语义。新增 UI 用例连续操作三个下拉，分别以取消、Esc、点遮罩、确认关闭对话框，断言弹层节点全部卸载；还验证打开下拉时第一次 Esc 只关下拉，第二次关对话框。共享控件的表单嵌套对话框、表格编辑弹层回归用例均通过。

## 缺陷二：导图自动保存冲掉改名输入

**根因与调用链。** 节点编辑使 `MindMapCanvas` 的 `draftFile` 变脏，自动保存调用 `write_mind_map`，成功后 `setDraftFile(saved.file)`。编辑器原有聚焦 effect 依赖整个 `draftFile` 对象，保存后的对象更新让它重新执行；标题改名输入位于导图画布 `rootRef` 外，effect 遂把焦点移到画布。`library-shell.tsx` 的标题输入 `onBlur` 调用 `submitRename()`；名称尚未改变时该函数 `setRenaming(null)`，输入框随即消失。`onSaveStateChange` 会更新保存状态，`onMapsChange` 会通知宿主，但此次输入消失的直接触发点是画布抢焦点，并非资料库树刷新或编辑器重建。

**修复。** 聚焦 effect 改为只随导图 `id` 或外壳 `surface` 变化执行，保留初次打开和切换导图时的聚焦，不在同一导图自动保存后抢走标题焦点。新增 UI 用例把写盘挂起，进入改名后释放写盘，确认输入仍可见、仍有焦点、未提前执行改名，随后输入新名称并确认；既有“改名前等待草稿落盘，改名后继续编辑并按新路径重开”和“不重建编辑器”相关用例仍通过。

## 偏差及原因

1. 施工令中的 `gui-smoke/report.md` 与截图未出现在本 worktree；它们存在于主工作树的同名目录。本次只读查看该报告和 `shots/06-filter-outline-number.png`，未修改 worktree 外目录。
2. 原生 WKWebView 的持续可见弹层未被自动化 WebKit 稳定复现；Chromium 复现了关闭后 portal 节点继续存在及 Esc 被拦截。修复在共享控件层直接按 `open` 卸载，并在两个浏览器验证目标交互。
3. Rust 聚合命令的 CLI 占位脚本来自现有 `src-tauri/build.rs` 与构建顺序；验收时临时替换生成 sidecar，待聚合命令通过后恢复占位脚本，不改本批范围外的构建机制。
4. 单测性能门槛受并行运行时负载影响；保留原断言，通过单文件与单 worker 复核，不调整本批无关的性能测试。
