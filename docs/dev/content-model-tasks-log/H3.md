# H3：搜索投影与类型筛选

## 改动文件与要点

- `src-tauri/src/search_sources.rs`
  - Markdown 内容类型改为复用 `shard_core::derive_type`，按 `note > outline > flowchart > document` 的统一优先级派生搜索 kind，补齐流程图片段。
  - JSON 大纲通过 `graph_region::find_region` 读取唯一 `shardmap` 区域，标题取根节点文字，搜索正文只投影节点 `text` 与 `note`；JSON 流程图读取唯一 `shardflow` 区域，标题取 JSON `title`，正文复用 `canvas_commands::search_text`。
  - 两类图形 md 的正文投影均为 `DocumentOnly`，不索引 JSON 键名、ID、排序键、时间戳或坐标；区域缺失、重复、类型不符或 JSON 解析失败时继续走原通用 Markdown 投影。
  - `read_search_document_from_disk` 允许读取 kind 为 `Flowchart` 的 `.md` 搜索目标，同时保留独立 `.shardflow.json` 的原处理路径。
  - 新增 5 项 Rust 回归测试，覆盖 JSON 大纲、JSON 流程图、旧式缩进大纲、多 type 标签优先级及损坏区域回退，并实际验证用户文字可检索、内部字段不可检索及命中位置为 `DocumentOnly`。
- `src-tauri/src/search_index.rs`
  - 将 `INDEX_FORMAT` 升为 `search-projection-assets-v3`，使已有派生缓存自动清空重建。
- `src-tauri/src/search_commands.rs`
  - 更新被忽略的 5k 搜索基准夹具与 kind 计数断言，加入流程图并保持五种 kind 各 1000 条。
- `src/lib/fragment-search.ts`、`src/lib/fragment-search.test.ts`
  - 旧前端搜索提供者只对成功解析的受管 JSON 大纲/流程图使用用户可见文字投影；旧式缩进列表和损坏区域继续走原 Markdown 清洗。
  - 新增 3 项单元测试，覆盖大纲节点/备注、流程图标题/节点/连线、内部字段排除，以及旧式大纲和损坏区域回退。
- `src/lib/fragment-space.ts`、`src/lib/fragment-space.test.ts`
  - `FragmentFilters` 增加类型维度，支持全部、碎片、大纲、流程图、文档；匹配以 `deriveKind(fragment.tags)` 为准，默认 `null` 表示全部。
  - 新增 1 项单元测试，覆盖四种时间线类型、全部状态及多个 type 标签的优先级。
- `src/components/shard/fragment-workspace-controls.tsx`
  - 在既有筛选对话框中复用 `SelectControl` 增加类型选项；激活后在现有筛选状态条显示中文类型名并可统一清除。
  - 没有新增 CSS、视觉 token、字体或控件实现；继续使用既有 Kiln 对话框、Select、Button 与间距。
- `tests/ui/search-ipc-mock.ts`
  - mock 的 kind、JSON 大纲/流程图标题与图内容投影对齐后端；合法空标题与解析失败分开处理，图正文命中返回 `documentOnly`。

## 偏差及原因

1. 施工令把 5k kind 计数断言归在搜索索引背景说明中，但源码中的实际断言位于 `src-tauri/src/search_commands.rs` 的被忽略基准测试。按源码事实只在该处把 4 类夹具扩为 5 类，没有在 `search_sources.rs` 复制基准。
2. `SearchKind::Flowchart` 同时表示 Markdown 流程图片段和独立 `.shardflow.json`。若在 `read_search_document_from_disk` 无条件放行，会改变独立文件的错误与读取边界；本批只对 `.md` 路径放行，独立流程图继续走 `load_canvas`，符合“不改变独立文件搜索行为”的限制。
3. 前端既有 `readFlowchartContent` 会调用 `validateCanvasFile`，该校验要求 `title` 非空，因此“合法 JSON 但空标题”的流程图片段在当前前端格式合同中不可达。没有为标题兜底扩大修改 Canvas 校验；后端解析层和 UI mock 仍实现「未命名流程图」兜底，正常创建路径本身也始终写入非空标题。
4. 施工令用“全部”描述类型筛选的无条件状态；现有 `FragmentFilters` 对标签与月份使用 `null` 表示不筛选。为保持同一过滤合同和最小改动，类型也使用 `null` 表示全部，UI 仍明确显示「全部类型」。
5. 新增第三个 Select 后，既有窄窗测试用未限定的 `[data-slot="select-content"]` 同时匹配关闭和打开的两个弹层。按实际 Base UI DOM 最小收窄为 `[data-open]`，没有修改控件实现或视觉样式。
6. `docs/dev/content-model-tasks-log/H3.md` 受仓库现有 `docs/dev/*` 忽略规则影响，不会出现在普通 `git status` 中；仍按施工令创建并直接读取核对，没有通过 stage、commit 或修改 `.gitignore` 绕过规则。
