# G2：时间线按属性筛选

## 改动文件与要点

- `src/lib/property-filter.ts`
  - 新增 `PropertyFilter = { key, op, value? }`、按登记类型分派的运算集合、条件校验与纯函数匹配。
  - 通用运算覆盖存在、不存在、为空和不为空；文本/链接、数字、日期、日期时间、勾选、列表分别只接受施工令规定的运算，类型不符与 `other` 值不会进入类型比较。
  - 数字比较不经过 JavaScript `number`：按符号、整数位和小数位逐位比较，支持等价小数、负数和超大整数，并拒绝科学计数法。
  - 日期按规范 `YYYY-MM-DD` 比较；日期时间按原始文本前 16 位的分钟精度字面比较，合法时区或秒后缀不参与换算，无效原值直接排除。
- `src/lib/fragment-space.ts`、`src/lib/fragment-space.test.ts`
  - `FragmentFilters` 增加单个 `property` 条件，空筛选同步补为 `null`。
  - `matchesFragmentFilters` 在既有类型、标签、月份、置顶条件后追加属性“且”条件，并接收登记类型表；原有筛选与时间线归属语义不变。
  - 增加属性与类型、标签、月份、置顶组合的单元测试。
- `src/lib/property-filter.test.ts`
  - 新增 8 项单元测试，覆盖全部运算的匹配与不匹配、`0.1`/`0.10`、负数、超大整数、非法 `1e3`、日期与日期时间边界、类型错配、`other`、精确列表项和非法范围。
- `src/workspace/workbench-shell.tsx`
  - 打开筛选对话框时异步读取既有 `.shard/properties.json` 登记表，提供局部 loading/error 状态，不在渲染或事件主路径做同步文件读取。
  - 时间线列表、新建内容可见性提示、搜索/定位可见性判断统一传入同一份登记类型表，避免不同链路对属性条件判断不一致。
  - 属性条件纳入无结果提示和时间线 scope key；支持单独清除属性条件，同时保留其它筛选。
- `src/components/shard/fragment-workspace-controls.tsx`
  - 筛选对话框增加属性名、随类型变化的运算和值控件；候选由当前公开时间线碎片的属性键与登记表键合并、去重、排序。
  - 复用现有 `SelectControl`、`Input`、`DatePicker`、`TimePicker`、`Checkbox`、`Dialog` 与 Kiln token，没有新增 CSS、视觉样式、依赖或原生表单控件。
  - 数字使用文本输入与十进制键盘提示，日期/日期时间复用共享选择器，`between` 显示同类的上下限控件；通用运算和勾选运算不显示值控件。
  - 点击“查看碎片”后才显示就近校验错误；非法数字、日期、日期时间或不完整/倒置范围不会应用条件。
  - 状态条显示中文属性条件，并提供“清除属性筛选”和既有“清除筛选”两个独立动作。
- `tests/ui/properties.spec.ts`
  - 新增 1 项真实工作台 UI 用例：组合类型与数字属性条件，验证 `1e3` 被拦截、合法条件只保留匹配卡片、状态条文案正确，以及单独清除属性后类型条件仍保留。
- `tests/ui/fragment-masonry.spec.ts`、`tests/ui/organize-fragments.spec.ts`、`tests/ui/search-palette.spec.ts`
  - 给会打开筛选对话框的 mock 补齐 `read_property_registry`；同步更新筛选对话框新增属性选择器后的既有几何控件数量断言。
- `docs/dev/content-model-tasks-log/G2.md`
  - 记录本批实现、开工前基线、验收、偏差与遗留问题。

本批没有修改 Rust、数据存储、SQLite、属性写入、既有类型/标签/月/置顶筛选语义，也没有实施其它批次、提交 Git 或改动 worktree 外目录。

## 偏差及原因

1. `AGENTS.md` 指向的 `docs/design/frontend.md` 在当前 worktree 中不存在。UI 实现因此遵循仓库内实际存在的 `vendor/kiln/SKILL.md` 与对应组件、布局规范，并复用现有共享控件；没有创建替代设计文档或新增视觉样式。
2. 施工令把 `PropertyFilter.value` 留为未展开的可选字段，但 `between` 必须承载两个端点。实现采用 `value?: string | [string, string]`，仍保持 `{ key, op, value? }` 外形；非法、缺失或倒置端点失败关闭，不自动交换。
3. 源码中登记表此前只由 `PropertiesPanel` 局部读取，`WorkbenchShell` 没有可供时间线匹配使用的登记类型状态。为保持 `PropertyFilter` 不额外存储类型并让所有可见性判断一致，本批做了最小适配：筛选对话框打开时由壳层异步读取登记表，`matchesFragmentFilters` 显式接收类型表；未登记键严格按文本处理。
4. `Fragment.properties` 在实际 DTO 中是可选字段，以兼容旧后端和测试 mock；匹配与候选收集均把缺失字段当空数组，没有收紧公共类型合同。
5. 仓库当前没有可复用的通用可搜索 Combobox。按 §14.2 的明确降级规则，属性候选即使超过 8 项仍使用现有 `SelectControl`，没有为本批新增组件或依赖。
6. 筛选对话框既有类型、标签、月份清空方式仍使用“全部”选项，与新版 Kiln 的触发器内清除规则不同；这是本批之前的既有交互，G2 只按同一布局增加属性组，没有借机重构其它筛选。
7. `docs/dev/content-model-tasks-log/G2.md` 受仓库现有 `docs/dev/*` 忽略规则影响，不出现在普通 `git status` 中；仍按施工令创建并直接读取核对，没有 stage、commit 或修改 `.gitignore`。
