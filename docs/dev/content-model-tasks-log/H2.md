## 偏差及原因

1. `tests/ui/mind-map-workspace.spec.ts` 写死 1420，与本施工令“绝不能连到 1420”直接冲突。为取得合法基线，必须在业务实现前先把 fixture 改为读取 worktree 配置的 `baseURL`；默认 Playwright 配置和用例行为未改。
2. §6.3 要求“按现有 `handleCreate` 的方式插入时间线、滚动与动效”。源码中的 `handleCreate` 实际通过 `setFragments` 插入并排序，由现有时间线布局负责呈现，没有单独的滚动或动画调用；本批按该源码事实复用相同更新路径，没有新增全局滚动机制。
3. `FragmentEditor` 原调用链没有“载入磁盘版”所需的刷新入口。为复用资料库冲突语义，最小增加 `onRefreshFragments`，沿 `FragmentEditor` → 卡片 → 时间线 → Workbench 透传；没有改变任务勾选保存路径。
4. 现有 `MindMapCanvas` 的 ready 通知只来自导图 Canvas editor，初始大纲视图不会触发。为让搜索导航等待实际宿主渲染，保留默认导图原通知位置，并只为 outline 视图补充渲染后通知。
5. 图形冲突选择「保留磁盘版本」后，Canvas 内部虽然已重新读取，但源码没有把返回 fragment 同步给时间线。storage 适配器因此增加可选 `afterRead` 通知；碎片适配器只回灌宿主状态，不把外部磁盘版本记为本次内容写入。
6. `quick-open-perf.test.ts` 在全套并行负载下出现一次 warm p95 波动，按施工令单独复跑后 2/2 通过；未调整阈值或性能实现。
