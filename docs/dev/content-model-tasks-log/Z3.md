# Z3 只读渲染硬换行标记修复报告

## 根因与判定方式

富文本编辑器把段内硬换行写成 `\` 加换行；原有逐行只读渲染把行尾 `\` 当普通字显示，编辑器却按 Lezer `HardBreak` 节点解析。现在共用 `@shard/markdown/core` 的 `stripMarkdownHardBreaks`：只在同一 Lezer 配置产出的节点恰好覆盖 `\` 加换行时去掉反斜杠。卡片解析复用同一棵语法树收集标记位置，保留每行 `source`、原始行号与任务操作索引，只改变 `display`。仅有标记的行仍占一个可见空行；字面转义反斜杠、段末反斜杠、代码和表格保持原样。编辑器序列化格式及已有文件未改。

`search-dom-highlight.ts` 从实际可见 DOM 文本节点建立匹配位置，不拿 `source` 长度当显示偏移；新增搜索定位 UI 用例核对了标记移除后的命中范围。

## 偏差及原因

1. 施工令描述 `parseMarkdownContent` 已解析整篇内容；源码中原本仅在 `compactParagraphs` 时解析。本批仅在需要压缩段落或出现候选 `\` 加换行时解析一次，并让两项显示处理共用该语法树。
2. 代码核对发现月历和图编辑器资料引用也直接显示 Markdown 正文；为满足 §19.2 的出口覆盖要求，增加了上述最小接入。
3. 同步 UI 出口对共享处理函数设置解析长度上限，避免长文在渲染或事件处理时触发大量同步 Markdown 解析；搜索 Worker 与包内长文异步解析保持全量。超出上限的标记可能按原文显示，详见遗留问题。

## 遗留问题

- 同步出口只解析正文前 **32,000** 字符；图编辑器短标题和预览分别使用更小的可见前缀预算。若可见文字来自预算之外，硬换行标记可能仍出现。完整长文的卡片解析走既有 Worker，搜索 Worker 也全量处理。
- 当前 HEAD 的 Markdown golden 夹具只有 1 组，`pnpm test:unit` 仍有这一项既有失败。原生 Tauri/WKWebView 未在本批重打包验证。
- 未提交 Git，未切换分支；`playwright.worktree.config.ts` 保持未跟踪。
