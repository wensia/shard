## 偏差及原因

1. `AGENTS.md` 指向的 `docs/design/frontend.md` 在当前 worktree 中不存在。UI 实现改为遵循同一份 `AGENTS.md` 中已写明的 pointer-first 产品选择，以及仓库内 `vendor/kiln/SKILL.md`、references 和 tokens；没有创建替代设计文档或扩大范围。
2. 施工令没有规定登记表文件缺失时返回的 SHA。为让首次登记也能使用同一乐观并发合同，缺失文件采用空字节内容的 SHA-256；首次写入后返回实际格式化 JSON 文本的 SHA。
3. 超出 u64 的标量会令 `serde_yaml::Value` 整体解析失败。为满足「整篇仍可读取」，属性提取按顶层原始条目逐项解析；失败条目返回 `other` 原文，而系统投影继续沿用既有 `FragmentFrontmatter` 反序列化。该适配没有改 `apply_frontmatter` 行为。
4. 资料库原布局给编辑器本体设置 `min-height: 100%`。直接把属性面板作为同级插入后，短文档也会超出视口并在复选框聚焦时滚动 20px；源码事实与施工令的简单插入描述不完全相符，因此改为面板固定占头部、编辑器填充剩余空间的最小 flex 适配，并通过原任务几何用例验证。
5. 为履行项目级全量 UI 检查，首次调用 `pnpm test:ui` 时错误地传入了额外的 `--` 参数分隔符，Playwright 因而回退到默认配置并连接了现有 1420 服务。发现 1420 监听后立即中止；没有修改或停止该服务，也没有产生仓库外写入。此操作违反了本任务「绝不能连到 1420」的明确要求。随后所有正式基线、§12.8 验收、定向复跑和正确的全量补充检查均显式使用 `-c playwright.worktree.config.ts` 并运行在 1422。本偏差无法撤销，故在此如实记录。
6. `docs/dev/content-model-tasks-log/G1.md` 受仓库现有 `docs/dev/*` 忽略规则影响，不出现在普通 `git status` 中；仍按施工令创建并读取核对，没有 stage、commit 或修改 `.gitignore`。
