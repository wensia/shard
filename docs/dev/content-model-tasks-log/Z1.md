## 失败用例根因与处理

| 用例 | 归类 | 根因 | 处理 |
| --- | --- | --- | --- |
| `fragment-scroll-performance.spec.ts` 3 项 | 测试问题 | `settleGeometry` 等待 composer 子树的全部 `animation.finished`，其中富文本自绘光标为无限动画，`beforeEach` 永不返回。 | 仅过滤并等待有限动画，保留原有几何稳定门禁与性能断言。 |

| `library-tree.spec.ts` 碎片转文档正文空行 1 项 | 测试预期过时 | 编辑器测试桥按现行 Markdown 方言规范序列化，标题与正文段落之间输出空行；转换命令没有增删正文。 | 精确期望更新为 `# 八月灵感\n\n碎片正文`，仍逐字验证正文。 |

## 偏差及原因

1. 施工令列出 `library-tree.spec.ts` 3 项既有失败，但本 worktree 的开工基线额外复现了 1 项文件菜单竞态。它是同一验收 spec 内可稳定解释的测试等待问题；为满足“相对基线无新增失败”并避免负断言失效，做了不降低断言强度的最小测试修正。
2. 搜索控制器只接受当前 `session.hits` 中的真实 `SearchHit`，伪造标签命中会改变冻结的搜索契约。因此标签候选按施工令落在面板层，数据由 `WorkbenchShell` 提供，主题页使用独立回调；未修改 Rust 搜索、搜索请求/响应或结果目录结构。
3. 首次直接运行 Rust 聚合命令时，`src-tauri/build.rs` 生成的开发占位 sidecar 位于 `target/debug/shard-cli`，导致 6 个 CLI 进程集成测试启动占位脚本。先执行 `cargo build -p shard-cli` 生成真实测试二进制后，原验收命令完整通过；未为此修改源码。
