## 1. 定位

**Shard 是一个更轻的、以碎片为主的个人资料库。** 它优化的核心动作是快速记录与灵感收集：想法、摘录、网页收藏、备忘、大纲都是碎片，先记下来，再在需要时整理成文档。

"资料库"指 Shard 这个产品与它管理的库（vault），不是曾经的目录树文档空间；后者已按只围绕碎片的方向移除。

目标用户不写 Markdown，也不应该被要求学习 Markdown。由此得到两条不可妥协的原则：

1. **用户永远不需要输入语法。** 所有格式来自动作：工具栏、快捷键、`/` 命令菜单、输入前缀自动转换。
2. **文件永远是开放的纯文本。** 任何编辑结果都能用普通文本编辑器打开、用 Git 追踪、被 Agent 读写：碎片与文档是可读的 Markdown，大纲与流程图是 md 里的一段 JSON，数据集是 CSV。Markdown 是存储格式，不是交互语法。

### 1.1 对标与借鉴

| 产品 | 借鉴 | 不借鉴 |
| --- | --- | --- |
| Obsidian | 双链与反向链接、属性驱动的视图、命令面板、插件即围栏块处理器 | 目录树优先的信息架构、以 Markdown 语法为交互 |
| Tolaria（refactoringhq/tolaria，Tauri + React） | type 是单值属性且类型定义本身是普通笔记、库内保存视图、库内放 AGENTS.md 让任意 AI CLI 可操作、内置 MCP | 以文档管理为中心的工作台形态 |
| NoteGen（codexu/note-gen） | 先记录后整理：多形态捕捉（文本、链接、截图、文件）落为碎片，选中若干碎片交给 AI 整理成结构化笔记 | 记录区与写作区两个平行入口；Shard 只有一条时间线 |

## 2. 内容模型：一条内容一篇 md，四种内容类型

时间线上的每条内容都是一篇 `.md` 文件，一个条目只有一个文件。类型由已有的 type 机制标识：type 是受保护的单值标签，缺省即碎片。碎片与文档的正文是 Markdown；大纲与流程图的正文是唯一一段受管 JSON（§2.1）。标签、属性、双链、私密状态都在 frontmatter 上，所以四种类型共用同一套筛选、反链、回收站、私密、Git 与同步链路；类型间转换不搬文件。

| 类型 | 权威内容 | 速记框里如何创建 | 打开后的编辑外壳 | 时间线卡片 | 保存模式 |
| --- | --- | --- | --- | --- | --- |
| 碎片（缺省） | md 正文，可内嵌大纲块、数据表 | 直接输入，Cmd+Enter 提交 | 行内编辑或禅模式，基础工具集 | 全文卡片 | 提交式 |
| 大纲（`outline`） | 正文里的受管 JSON（`shard.map` 格式），大纲与导图是它的两个视图 | `/大纲` 把整个输入框切成幕布式大纲态，Cmd+Enter 提交 | 幕布式大纲占满编辑区，可切换导图视图 | 导图缩略 + 标题 | 速记框内提交式，打开后自动保存 |
| 流程图（`flowchart`，默认决策） | 正文里的受管 JSON（`shard.flow` 格式） | `/流程图` 直接进入流程图编辑器新建 | 流程图画布 | 流程缩略 + 标题 | 自动保存 |
| 文档（`document`） | md 正文 | `/文档` 直接进入禅模式新建 | 禅模式完整工具集 | 标题 + 摘要 | 自动保存 |

"内容变长就变成文档"不成立：类型只由用户动作或显式转换决定。

**碎片**是默认对象。编辑态只暴露基础能力：粗体、高亮、下划线、三种列表、分割线、标签、双链、图片、备忘卡片、大纲块、数据表。标题、表格、代码块在碎片里仍能正确显示与保存，但不出现在碎片的工具栏里。

**大纲**的默认态永远是幕布式大纲：每行一个节点，Enter 新建、Tab 缩进、Shift-Tab 反缩进。导图是同一份 JSON 的另一个视图，沿用现有导图编辑器（两个视图已共享同一份草稿），因此可以编辑；节点颜色（`tone`）、备注、折叠、宽度、文档链接等导图信息与大纲文字存在同一份 JSON 里。现有 schema（v1）没有关联线和概要，要加须升 schema 版本。速记框里只创建大纲，不创建导图，输入框永远是文本输入；提交时把输入的树写成 JSON。碎片或文档正文里嵌入的一小棵树仍使用 ```` ```mindmap ```` 围栏内的缩进列表，只有文字结构、不带样式，与大纲共用幕布式编辑组件，但序列化不同（默认决策，理由同 CSV 方案里内联小表与数据集之分）。

大纲离开 Markdown 的代价是 Agent 和外部编辑器不能再按纯文本读写它。补偿措施：

- 库内 AGENTS.md 写明 JSON 结构、稳定 ID 与写入规则，同时提供 JSON Schema 与校验器；说明文字不能代替校验。
- CLI 分三类接口：原生 JSON 读写（完整交换，写入校验基线）；缩进列表导出（只读投影，不承诺往返）；按节点 ID 的结构化修改（给 Agent 用，未涉及的数据原样保留）。「改缩进列表再导入」只能作为显式的有损替换，先展示损失清单。
- 搜索做图内容投影：标题、节点文字与备注、流程图连线标签、节点链接；不索引 JSON 键名、坐标和 ID，结果以条目为单位。
- JSON 用稳定键序和缩进写出，保证 Git diff 可读；文本合并后仍要做结构校验（ID 唯一、父子关系、根数量、无环、连线端点），没有语义合并器前保留完整冲突版本，不取最后写入者。

**流程图**与大纲同样以 JSON 为权威内容，节点、连线、判断、起止和文档引用的规则沿用 [图文档分离实施计划](diagram-document-separation.md)；流程图里不能嵌入可编辑导图。

**文档**在禅模式下拥有完整能力：标题层级、表格、代码块、目录、字数、反链面板。文档不需要独立空间：它在同一条时间线里，靠 type 筛选和标签主题页承载。

### 2.1 大纲与流程图的受管 JSON 区域

2026-09-28 用户裁决采用单文件容器（[内容模型架构评审](content-model-architecture-review.md) §2 方案 B），不再用「入口 md + 旁路 JSON」。

- 大纲 md 的正文是一个 ```` ```shardmap ```` 围栏，流程图是 ```` ```shardflow ````（围栏名为默认决策），里面是完整的 `shard.map` / `shard.flow` JSON。一篇 md 只能有**一个**受管区域；零个、多个或无法解析时显示格式问题并停止自动保存，不猜选其中一个。
- 受管区域不是碎片里可嵌入的围栏块：不送进 Tiptap、Markdown 美化、`mindmap` 小树解析器或普通正文提取器；这类 md 只由导图或流程图编辑器打开。
- 保存方式是「读取当前完整文件 → 只替换受管区域 → 原子写回」，基线校验覆盖完整文件（含 frontmatter）。图编辑器不持有 frontmatter，不重建整篇 md。
- 受管区域之外由外部写入的正文原样保留，不在图编辑器里编辑。
- 标题存在 JSON 里（导图根主题、流程图 title），frontmatter 不重复存。frontmatter 的 `updated_at` 是整条内容的修改时间，JSON 的 `updatedAt` 是图内容的修改时间；视口、选区等会话状态放本机，不改业务时间。
- 导出的 `.shardmap.json`、`.shardflow.json`、缩进列表、SVG 都是派生产物，不作为第二份权威数据。
- 单文件省掉的是双文件事务，不是一切问题：原子替换、并发校验、幂等创建（稳定操作 ID）、索引失效与跨设备冲突仍要处理。
- `/大纲` 提交：完整解析和校验 → 幂等创建一篇 md → 返回正式 ID、内容与修订 → 清草稿 → 用同一份内容打开编辑器。失败保留草稿，不先建空 md 再补图。
- Obsidian 打开这类 md 看到的是 frontmatter 加一段 JSON 代码块；文件级属性和链接可以互通，图的渲染与编辑不互通。

### 2.2 自定义属性

- **存储**：frontmatter 顶层扁平键，值为 YAML 标量或列表，与 Obsidian properties 兼容（Obsidian 没有 link 类型；`types.json` 只做显式导入导出，不互相后台覆盖）。
- **保真**：本次操作没有涉及的键和值保持原文，包括注释、键序和引号风格，只局部改写被操作的键；无法安全局部修改时拒绝写入、保留原文件，不回退到整体重新序列化。写入是明确的操作（设置置顶、改一个属性、替换正文），不从 UI 回传的整条内容重建 frontmatter。
- **保留名**（闭合集合）：`id`、`created_at`、`updated_at`、`tags`、`pinned`、`source`、`related`、`conflict_of`、`category`、`ai_status`。属性面板里只读或隐藏；type 仍走标签机制。以后新增保留名前，先处理库内已有的同名用户键。
- **类型**：全库登记在 `.shard/properties.json`，一个属性名只有一种类型（文本、数字、日期、日期时间、勾选、列表、链接）。登记表是解释规则，不是值的真相源：缺失、损坏或冲突时只影响类型化编辑、排序和筛选，不删改任何文件里的值；多设备按属性定义合并，同名不同类型保留冲突待裁决。未登记的属性保留原值与原表示；值与登记类型不符时提示，不改写，也不参与正常比较。第一版只支持改显示名，不做全库改存储键。
- **值**：日期不加时区；无偏移的日期时间按本地未指定时区处理；数字不经 JS number 往返；`"00123"` 不因登记为数字变成 123；`x`、`[x]`、`[]` 不互转；缺键、null、空串、空列表分别保存；新写布尔只用 `true/false`；嵌套值先不给编辑 UI，但必须保留。
- **编辑**：通过属性面板添加属性、选择类型，用户不写 YAML。四种类型都有属性。
- **视图**：属性进入时间线筛选条件；标签主题页增加表格视图，每篇 md 一行、属性为列。
- **与 CSV 的边界**：每一行需要自己的正文，用 md 加属性；纯记录用 CSV。
- **私密**：私密内容的属性随正文加密，不进 SQLite 索引；私密条目新建的属性名进入公开的 `properties.json` 前要让用户知情。

### 2.3 资源文件

md 表达不了、又要被多篇内容共享的数据放进资源文件，由 md 引用或嵌入。资源不进时间线、不带 type。

| 资源 | 文件 | 归属 | 引用方式 |
| --- | --- | --- | --- |
| 数据集 | `datasets/<名称>.csv` + 可选旁路 schema | 不归属任何 md，可被多篇共享 | `datatable` 围栏的 `src`，或 `![[x.csv]]` |
| 附件 | `assets/` | 按引用收集 | 正文图片与文件链接 |

- 引用资源不等于拥有资源：一篇 md 删除时不带走它引用的数据集。数据集规则见 [CSV 数据存储层方案](csv-data-storage-plan.md)。
- **新增文件格式的门槛**：md 表达不了这种信息形状、需要被多篇内容独立引用、需要专属编辑器，三条同时满足才新增资源格式。只满足第一条和第三条的（如大纲、流程图）放进 md 的受管区域；其余做成围栏块、视图或属性。

## 3. 主界面与信息架构

主界面沿用只围绕碎片设计的结构：左侧导航（搜索、全部碎片、私密碎片、标签、回收站、状态、设置），主内容区是固定的速记框加一条时间线。本文在此基础上明确：

- **只有一条时间线。** 四种类型都在这条时间线里，以各自的卡片形态呈现。type、标签、日期、置顶、来源都是筛选条件，不新增一级导航，不建目录树。
- **标签主题页**是聚合入口：点开一个标签看到该标签下的碎片、大纲、文档，以及反向链接。type 标签的主题页天然就是"全部大纲"或"全部文档"。
- **双链与反链**：碎片、大纲、文档之间用 `[[ ]]` 互相引用，打开任一内容都能看到谁引用了它。
- **禅模式是通用能力**：四种类型都可以进入禅模式，差别只在功能集合。碎片在禅模式下仍是同一个编辑器，工具栏是基础档；大纲在禅模式下是大纲与导图切换加全屏画布；流程图在禅模式下是全屏流程画布；文档在禅模式下开放全部能力。不为新的内容类型自造全屏外壳。
- **私密碎片**是同一条时间线的门控状态，规则不变，见只围绕碎片设计第 3.3 节。

## 4. 无语法编辑

编辑器内部是富文本模型，所有可见元素都是 Shard 自造的组件；Markdown 只在读写文件时转换。用户不会在编辑态看到 `**`、`#`、`- `、`[[`。

| 用户动作 | 效果 |
| --- | --- |
| 输入 `- `、`1. `、`[] `、`# ` 等前缀 | 当前段落立即转换为对应块，前缀消失 |
| Cmd+B、Cmd+U、工具栏 | 应用行内格式 |
| `/` | 命令菜单：大纲、备忘卡片、数据表、任务列表、无序列表、有序列表、表格、分割线、标签、图片、文档 |
| `#` | 标签提示，选中后成为标签芯片 |
| `[[` | 双链提示，选中后成为双链芯片 |
| 粘贴 Markdown 文本 | 按方言解析为组件，不保留原始语法 |
| 粘贴 URL | 识别为链接，提示生成收藏碎片或采集全文 |

用户输入的字面星号、井号等字符会以转义形式保存，重新打开后仍显示为普通字符。

碎片卡片的只读渲染继续使用现有的 Markdown 渲染管线；它与编辑器共用同一份 Markdown 方言，方言定义见技术方案。

## 5. 组件与插件

### 5.1 统一底座：围栏块即组件

Shard 要像 Obsidian 一样支持插件和自定义组件。Obsidian 的自定义组件机制本质上是"围栏块处理器"：注册一个围栏语言，负责该块的渲染与交互。Shard 采用同一原则，并把它作为所有自造组件的统一底座：

- 大纲块、数据表以及未来的任何围栏块组件，都通过同一个块注册表接入编辑器、卡片渲染和命令菜单。Shard 自己的组件是这套 API 的第一批消费者，先在内部验证，再开放给第三方。
- 未注册的围栏块在编辑态显示为原始块，不会丢失，安装对应插件后自动变为组件。
- 第三方插件是库内目录 `.shard/plugins/<id>/` 下的清单加脚本，默认关闭，用户显式启用并看到风险说明后才加载。插件不直接调用系统接口，只能通过 Shard 提供的 API 注册块、命令、菜单项和设置项，读写库内文件。

### 5.2 首批组件

| 组件 | 用途 | 存储 | 说明 |
| --- | --- | --- | --- |
| 大纲块 | 在碎片或文档里嵌一小棵树 | ```` ```mindmap ```` 围栏内缩进列表 | 与大纲共用幕布式编辑组件，只存文字结构、不带样式；可一键提升为独立大纲（生成一篇大纲 md） |
| 备忘卡片 | 带复选框的卡片，标题一行，下面是细节 | GFM 任务项带子内容，不发明新语法 | 没有细节的任务项仍是普通任务行；带细节的在编辑态和卡片上都显示为卡片 |
| 数据表 | 可排序、筛选、分组、搜索、全屏、导出的表格 | ```` ```datatable ```` 围栏内 JSON：列定义加内联行，或 `src` 指向库内 CSV | 参考 craft-agents 的 `datatable` 块；`![[x.csv]]` 嵌入等价于指向该文件的数据表；GFM 管道表格保留给静态小表 |

备忘卡片的存储示例：

```markdown
- [ ] 买菜
  番茄、鸡蛋、葱，周三前
```

### 5.3 网页采集：第一个官方插件

网页收藏是碎片的一部分，是记录灵感的关键来源之一。网页采集作为插件架构的第一个官方插件，随应用内置、默认启用，同时验证插件 API 的网络请求与库内写入能力。

| 入口 | 默认产物 | 说明 |
| --- | --- | --- |
| 在速记框粘贴 URL | 碎片 | 自动补标题与摘要，形成带来源的收藏碎片；可选"采集全文" |
| 浏览器扩展：选中片段采集 | 碎片 | 选中文本加来源链接，进入时间线 |
| 浏览器扩展：整页采集 | 碎片，长文可选存为文档 | 正文提取、图片本地化为附件，通过 `shard://` 协议交给桌面应用 |
| 聊天里发 URL 给 Agent | 碎片 | 手机端采集路径，Agent 调用同一采集工具 |

采集产物就是普通碎片：正文是 Markdown，Frontmatter 记录来源 URL、标题、作者、发布时间与采集时间，自动带 `#采集` 标签，按标签或来源域名筛选即可回看。采集永远生成新内容，不覆盖已有碎片；同一 URL 重复采集时提示已存在并可打开旧的。

## 6. 捕捉入口全景

| 入口 | 设备 | 产物 |
| --- | --- | --- |
| 速记框直接输入 | 桌面 | 碎片 |
| 速记框 `/大纲`、`/流程图`、`/文档` | 桌面 | 大纲、流程图、文档 |
| 速记框粘贴 URL、图片、文件 | 桌面 | 收藏碎片、带附件的碎片 |
| 浏览器扩展 | 桌面 | 收藏碎片或文档 |
| 聊天软件发消息或 URL 给 Agent | 手机 | 碎片 |
| AI 整理选中的碎片 | 桌面 | 文档 |

不开发独立手机 App；手机端只通过聊天与 Agent 完成捕捉与查找。

## 7. 类型转换（默认决策，可推翻）

| 转换 | 首版 | 说明 |
| --- | --- | --- |
| 碎片 → 文档 | 支持 | 只改 type，正文不变，进入禅模式 |
| 碎片内大纲块 → 独立大纲 | 支持 | 从碎片中抽出围栏块生成一篇大纲，用正式导入器完整校验，失败不改原碎片；原碎片保留双链指向新大纲 |
| 大纲 → 文档 | 支持（2026-09-28 修订） | 生成一篇新文档，正文是树导出的缩进列表，保留来源双链；原大纲不变。大纲改存 JSON 后不能再只改 type |
| 多个碎片 → 文档（AI 整理） | 支持 | 沿用既有 AI 整理动作：选中碎片与模板，预览后生成新的文档并保留来源双链，不覆盖原碎片 |
| 文档 → 碎片 | 不做 | 首版不提供降级；文档可以整体删除或保留 |
| 碎片 → 大纲 | 不做 | 正文不是纯列表时无法可靠转换；用户可新建大纲后粘贴 |

阶段 H 的旧数据处理（默认决策）：

- 旧 md 大纲（type `outline`、正文是缩进列表）：保留同一篇 md，id、标签、属性、反链都不变，正文换成受管 JSON 区域。用正式导入器（不用上限 200 节点的预览解析器），完整扫描，遇到无法表示的段落、代码块、链接或超限节点时报告并停止该篇，失败不改原篇。首次检测到时先出预检报告、一次性提示批量升级，不因打开文件而静默改写；升级前只读显示并提供「升级」。升级前要求已确认成功的检查点或独立备份（现有结构操作前检查点失败时只打日志，不算保证）；只有目标仍是迁移生成版本时才自动回滚。
- 资料库时代 `notes/` 下的 `.shardmap.json`、`.shardflow.json`：显式「加入时间线」，封装进一篇新 md，保留旧图 ID、节点 ID 与创建时间，`shard://map/ID`、`shard://flow/ID` 继续可解析；封装后原 JSON 不再是权威副本。

备忘卡片的优先级、插件市场不在本路线图内；导图可编辑随阶段 H 沿用现有导图编辑器解决。备忘卡片的提醒时间已落地（见 §11 第一条）。

## 10. 验收口径

- 一个不懂 Markdown 的用户在速记框、行内编辑、禅模式中完成一次含标签、列表、备忘卡片、大纲的记录，全程没有看到任何语法标记。
- 同一文件在编辑器保存后，用文本编辑器打开是可读的 Markdown，重新用 Shard 打开与保存前一致。
- 四种类型在时间线上按各自卡片形态呈现，type 筛选可只看大纲、流程图或文档。
- 大纲切到导图视图改节点颜色，关闭重开后大纲与导图一致；用 CLI 按节点 ID 改一个节点的文字，Shard 里看到修改，其余节点的样式、备注、链接不变。
- 用文本编辑器在 frontmatter 里加一个属性，再在 Shard 里编辑并保存这条内容，属性原样保留。
- 在速记框粘贴一个 URL 得到一条带标题、摘要与来源的收藏碎片。
- 新增一个围栏块组件不需要修改编辑器、方言转换或卡片渲染的代码。
