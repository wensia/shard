# CSV 数据存储层方案

日期：2026-09-27。状态：方案讨论稿，代码未实施；第 9 节的待决问题需用户拍板后才能进入阶段 0。

来源：与 ChatGPT Pro（Pro 档）两轮讨论（[会话](https://chatgpt.com/c/6ab82e3f-27f0-83ea-a14b-91354a0ea8f1)），Claude 对照源码逐项核实并裁决。凡标「已核实」的均读过源码；标「待验证」的是需要原型或测试确认的假设。

## 1. 定位与范围

- **CSV 是 Shard 的数据存储层，补 Markdown 不能存结构化数据的短板**：md 写叙述，CSV 存记录（行 × 列）。
- 只做数据保存：**不做公式、样式、多 sheet**。XLSX 永不做存储，只做导出。
- 存储层必须能在应用内录入和修改，推翻 2026-08-30「MVP 只预览不编辑」。
- 一句话：保留旧网格，不保留旧多维表格产品；让 CSV 成为受保护、可编辑、可恢复的数据源，而不是被网格包住、随时可能被覆盖的附件。

## 2. 分层：谁是什么的权威

| 信息 | 权威位置 | 不放在哪里 |
| --- | --- | --- |
| 表头、记录顺序、单元格原始值 | CSV | SQLite、md 里的另一份行副本 |
| 数据集 ID、主键、显式列类型、允许值、全局列说明 | 可选旁路 `x.csv.schema.json` | 某篇引用笔记、可丢弃索引 |
| 列绑定、显示名覆盖、呈现格式、筛选/排序/分组/可见列 | 引用方 md 的 ```` ```datatable ```` 围栏 | CSV、schema |
| 选区、光标、未保存筛选、展开状态 | 会话 / 本机 UI 状态 | CSV |
| 推断类型、统计、行偏移、查询投影 | SQLite / 内存缓存 | 权威 schema（除非用户明确采纳推断） |

- **CSV 不是第四种内容类型**：不进 type 标签枚举、不加一级导航；时间线上出现的始终是 md。它是可独立寻址、可被多篇笔记共享的资源，引用它的 md 是说明与入口，不是所有者。
- 同一份数据只能有一个权威来源。两种来源并存（见第 3 节），共享呈现与视图逻辑，不共享保存器。

## 3. 内联 JSON 小表与 CSV 数据集

**已核实现状**：`datatable` 围栏的内联行已可编辑（`datatable-block.tsx`：`editable = !readOnly && !spec.src && Boolean(onChange)`），`src` 指向 CSV 时只读；`src/lib/datatable.ts` 已有增删行列、改单元格、写视图等函数，结果序列化回围栏 JSON。

| 项目 | 内联 JSON 小表 | CSV 数据集 |
| --- | --- | --- |
| 数据归属 | 当前 md 的一部分 | 独立资源，跨笔记共享 |
| 类型声明 | 围栏 `columns[].type` | 旁路 schema |
| 保存与冲突 | 走 md 保存与 `expected_sha` | 独立保存，`expected_sha` + `expected_schema_sha` |
| 定位 | 随文小表、局部整理 | 持续积累、跨笔记复用、Agent 写入 |

- **保留内联编辑，不冻结、不强迁**；只是不再给内联模式加数据库式能力。
- 软阈值引导：超过约 200 行 / 5,000 单元格 / 256 KiB 时提示「提取为 CSV」（数值待性能验证）；超阈值不自动转换、不截断、不变只读。
- **「提取为 CSV」是来源转换，不是建同步副本**：预览 → 创建 CSV（+ schema）→ 围栏改为 `src` 引用并删除内联 rows，协调当前 md 的未保存状态与 `expected_sha`。数字从原始 JSON 表示转换，不经 JS number；null / 数组 / 对象逐项报告；列用唯一 `key` 作表头。私密碎片不提供此入口。
- 组件把 `editable` 拆成「可编辑数据」和「可编辑视图」。CSV 数据写入不走 md 的 `onChange`，视图修改仍写回围栏。**不能只删掉 `!spec.src` 条件让内联写入分支接管 CSV。**
- **内联精度问题单独修**（已核实）：`coerceDatatableValue` 把数字列文本转 JS number、布尔列把「是/yes/1」转 true。修复目标是不静默接受溢出、非有限值和超精度输入，并提供「改为文本列 / 提取为 CSV」出口；不批量改写旧 JSON，编辑一格不能舍入另一格。

## 4. CSV 数据契约

### 4.1 存储位置

- **Claude 裁决（与 Pro 不同）**：Pro 建议 `assets/datasets/`，理由是免改 pathspec。但 `assets/` 已是附件语义：写入按内容哈希分桶（`assets/<hash[..2]>/…`），资产列表按引用收集（`lib.rs` 约 2771 行），同步方案把「被引用的 assets」当附件做哈希校验（`fragment-storage-sync.md` 第 205 行）。可变的 CSV 放进去会被当作附件列出，并与不可变哈希假设冲突。
- 推荐新增受管根目录 `datasets/`：`datasets/阅读记录.csv` + `datasets/阅读记录.csv.schema.json`。需要在 `MANAGED_VAULT_ROOTS` 加一项，并检查备份、导出、同步的纳管清单（待决问题 1）。
- 已核实：Git 检查点 pathspec 已包含任意位置的 `**/*.csv`，外加 `fragments, notes, .trash, assets, maps, lockbox, .shard` 目录。根目录以外的旁路 schema 不会被纳管，所以 schema 必须落在受管根内。其他位置的既有 CSV 可以按普通 CSV 编辑；要建 schema 时显式迁入 `datasets/`。

### 4.2 写入格式（受管 CSV）

| 项目 | 约定 |
| --- | --- |
| 编码 | UTF-8，**无 BOM** |
| 记录分隔 | LF（引号内的 CR/LF 是字段值，不做全文替换） |
| 分隔符 / 引号 | 逗号；双引号，内部双写转义；必要时才加引号 |
| 文件末尾 | 固定一个记录终止符 |
| 值 | 不 trim、不转数字、不把 `NA` 等变空值；空单元格就是空字符串 |
| 顺序 | 表头与记录顺序稳定，视图排序不改源顺序 |

- **不保留原方言、不做「只重写改动行」**：导入时统一格式，之后整文件写临时文件再同目录原子替换。格式固定时，改一格在 Git 里仍只显示一条记录的变化。按记录复用原始字节区间属于阶段 3 可选优化。
- **BOM**：库内主文件不带 BOM；给 Excel 用的「带 BOM 的 CSV」和单 sheet XLSX 走导出。代价是不能保证所有 Excel 双击主文件都零配置识别中文编码，此时用 Excel 的导入 CSV 能正常读（待决问题 3）。
- 导入流程：识别编码与方言 → 预览 → 用户确认 → 写入规范化 CSV，原文件不动。已在 vault 内但格式不规范的 CSV 打开时不改写，保存前明确处理。解码错误不能用替换字符糊过去。
- `csv` crate 1.4.0 的解析偏宽松，解析成功不等于允许写回。另外要检查表头非空且唯一、字段数一致、主键、大小上限。已核实：`csv` 1.4.0 目前只是 `anydoc` 的传递依赖，要在实际使用的 crate 里声明为直接依赖；`tempfile = "3"` 已是直接依赖。
- **导出防公式注入**：原始 CSV 不加前缀；「Excel 安全导出」和 XLSX 把 `=` 开头等内容明确写成字符串单元格。

### 4.3 值、类型与 schema

- **值一律按原始字符串保存**，类型推断只作建议，不决定写回，也不会因为追加一行就改掉整列解释。精度敏感值不经 JS number 或 SQLite REAL 往返。
- 薄 schema 契约在阶段 0 就定下来：应用新建的数据集默认生成，外部 CSV 没有 schema 也能打开和编辑。最小内容为 `{ schemaVersion, datasetId, title, primaryKey }`，显式列类型以后再加。schema 里不存 revision、更新时间、hash 或行数据。schema 损坏或版本不支持时报错，可以提供「按普通 CSV 打开」降级。
- 列身份暂时用唯一表头，不复制旧的字段 UUID 体系。改表头属于结构变更，要校验 schema 和引用视图；只改显示名不动 CSV。

### 4.4 行身份

- **应用新建的数据集默认带 `id` 列**（`r_` 前缀随机值，是真实 CSV 数据；编辑器默认保护，可以在视图中隐藏）。导入时不擅自加列，让用户选一个已有唯一列作主键，或明确执行「添加稳定 ID」。
- **没有 ID 也能编辑**：用固定文件基线、会话内临时行句柄和整文件 hash 前置条件支撑编辑、粘贴和撤销。代价是没有持久单行引用，外部修改后也不按行号重放。
- 引用目标预留为 `{ datasetId, sourcePathHint, primaryKey, recordId }`。记录删除后显示「已删除」，不跳到下一行；复制数据集导致 datasetId 重复时报冲突。

## 5. 并发、保存与检查点

- **已核实缺口**：`lock_vault_gate` 是进程内 `Mutex<bool> + Condvar`，不可重入。`shard-cli` / `shard-core` 用「临时文件 + fsync + rename」写入，不取这道写门。两边都通过 hash 前置校验后依然可能互相覆盖。
- **阶段 0 前置交付共享跨进程协调器**，同时接入 md、CSV、CLI、检查点和应用内同步。锁顺序固定为：进程内 vault gate → 跨进程 vault 锁（放在本机运行目录，不进 Git 和同步）→ 在锁内校验并执行 → 逆序释放。组合操作（创建 CSV + schema + 改 md）只在最外层取一次锁，内部调用带事务令牌的底层函数，不能嵌套调用自带取锁的命令。「CLI 只落盘、提交交给 App」的约定不变。已核实：rustc 1.93.1，可以使用 1.89 起提供的 `File::lock`。
- **版本令牌沿用 md 的协议**：`expected_sha`（CSV 实际字节，含原有 BOM）+ `expected_schema_sha`（「不存在」也是一种可校验状态），不一致时返回 `STALE_BASE_ERROR` 这一类错误。已核实 md 保存已有这套先例。CSV 冲突界面除了「覆盖 / 载入磁盘版」，还要保留待保存操作，并提供查看差异或另存副本。
- 写入流程：在不可变基线上计算结果 → 取锁 → 复核 CSV、schema 和路径 → 校验整批操作 → 写同目录临时文件并刷盘 → 替换前再核对一次 → 原子替换 → 发布新版本、使投影失效、返回回执。
- **自动保存，以「完成的编辑操作」为单位**：输入法组词不落盘；同一数据集同时只允许一个写入请求；Cmd+S 立即落盘但不生成提交；关窗、切库、同步和结构变更前先 flush；保存失败不能显示「已保存」。之后仍由合并保存 v2 的检查点聚合提交。
- 撤销已落盘的数据时提交一个逆操作，不回滚整个文件。不要在持有写门时等待一个也需要这道写门的前端 flush。
- **对不参与加锁的外部写入者（Excel、编辑器、外部 Git）只保证能检测到**：暂停保存、保留待保存操作、引导合并，不承诺绝不丢失外部写入。「用 Excel 编辑」做成显式交接：先 flush、暂停应用内写入，回来后重新读取核对。
- Git 合并：受管 CSV 用 `merge=binary`，保留文本 diff，不要用 `binary` 宏，也不要用 `merge=union`。有了按 ID 的三方合并之后再接入 CSV 专用合并。每次同步后校验 CSV、schema、主键唯一性和数据集身份。
- 一格编辑不改变引用它的 md 的更新时间，这些笔记也不因此浮到时间线顶部。
- **发布阻断条件**：保存器拿预览、筛选或分页后的行集覆盖完整 CSV；前端显示已保存但 CSV 没有进入检查点或备份。

## 6. 视图、查询与 SQLite

- **现有 DTO（已核实）**：`DatatableSpec { title?, columns, rows, src?, view? }`；`columns[].type ∈ text|number|currency|percent|boolean|date|badge`，混合了数据类型和显示格式；`view = { sort?: {key, direction}, group?, filter?: 自由文本 }`。
- 演进规则：
  - 围栏里没有 `version` 的按旧版处理，读取和普通编辑都不自动升级；启用新语义时才写 `version: 2`。
  - CSV 来源的 `columns[]` 只管列绑定、显示名和呈现；新增 `format` 字段承接旧 `type` 里的呈现部分；真实类型只从 schema 取，没有 schema 时一律按文本。
  - `view.filter` 永远保持文本搜索语义；新增结构化条件 `view.where`（`all` / `any` 条件树，限制深度和节点数），两者同时存在时取交集。
  - 修改一个视图字段时不能丢掉其他字段；遇到不支持的主版本拒绝编辑。先让读写兼容层上线，再开始生成新版本。
- 旧 `type` 拆分只作迁移建议，不做自动转换：`currency` 不推断币种；`percent` 不改变比例口径；`badge` 默认仍按文本，不自动生成枚举。
- 首批查询只支持：列投影、AND/OR、等于/不等于/包含/为空、明确类型下的比较与排序、结果上限。不做聚合、计算列或 JOIN，不开放任意 SQL 或 JS。引用不存在的列时报错，不能静默忽略条件。
- **查询语义独立于 SQLite**：先用 Rust 内存执行器实现，SQLite 只是执行优化，两者结果必须一致。
- SQLite 用固定表结构，不按 CSV 动态建表：`dataset_files`（身份、路径、源 hash、schema hash、活动代次）、`dataset_columns`、`dataset_rows`（原始值字符串数组 + 可选 recordId）。类型化投影和原始字符串分开存，解析失败标为「无效」，不变成空值或 0。索引按「CSV hash + schema hash + 解析规则版本」使失效，按代次构建后原子切换。
- 过滤视图里编辑的行必须能定位回源记录；因为改了筛选字段而离开当前视图的记录要有提示。
- MVP 不做单元格全文搜索：全局只搜名称、文件名和表头，表内搜索只在当前数据集内。中文短词不能指望 FTS5 trigram 直接解决。

## 7. 入口、Agent 与边界

- **入口**：
  - 在笔记中插入数据表时，可以新建 CSV、选择已有 CSV 或导入。
  - 「新建数据集」会同时生成一篇普通说明碎片，内含 datatable 块。
  - 打开浮层（⌘O）能搜到数据集名称、文件名和表头，没有被 md 引用的 CSV 也要能找到。
  - 点击「编辑数据」进入通用的展开/禅模式承载区。同一份 CSV 不论从哪里打开，都共用同一个 `DatasetSession` 和同一套 Rust 读写命令。
  - 首版不在时间线卡片里直接编辑单元格。
  - 删除要区分「移除此引用」和「删除数据文件」，删除一篇笔记不级联删除它引用的 CSV。
- **旧多维表格**：
  - 复用：Glide 网格与 kiln 适配、TSV 剪贴板、保存队列机制、撤销思想，以及纯行列 mutations/validation。
  - 退役：多视图管理、旧导航、旧类型系统、旧 JSON 运行时模型。
  - 当前不换 react-data-grid。已核实：Glide 锁定 `6.0.4-alpha24`，React 实际锁定 19.2.7。
  - `.shardtable.json` 不自动迁移：提供显式迁移向导，原文件保留，迁移报告不静默丢字段。
  - 六种旧字段类型的映射：Text 原样；Number 不经 JS number；Date 先验证实际格式；Select 的值进 CSV、允许值进 schema、颜色不迁；Checkbox 写 true/false，空值不当 false；MultiSelect 要确认后才编码为 JSON 数组字符串，否则保留旧文件。
- **Agent / CLI 契约**：
  - 接口：`inspect_dataset`、`read_records`、`append_records`、`patch_records_by_id`，全部经过同一个 Rust 服务和协调器，不暴露「覆盖整张表」。
  - 追加：调用方自带稳定 ID；同一 ID 且内容相同返回「已存在」，内容不同报冲突；超时重试必须复用原 ID。
  - 更新：用 `recordId + 预期旧值/记录 hash + 修改字段`，整批要么全成功要么全失败。
  - 限制：路径必须在 vault 内，防止符号链接逃逸；批次、单格和总字节数都有上限。
- **私密**：首版不做私密 CSV。私密碎片里不提供新建或提取 CSV 的入口，保留内联小表跟随 md 一起加密；私密碎片引用的明文 CSV 要明示「目标是公开文件」。
- **何时说明 CSV 不够用**：需要外键或跨表事务；必须区分 NULL、空串和缺失字段，或要存嵌套结构；需要高频多写入方实时协作；需要行/列级权限；大文件长期达不到性能预算。届时交给外部工具，或另起架构决策改换权威存储。不能悄悄把缓存 SQLite 升格成真实数据库。

## 8. 分阶段路线

| 阶段 | 交付 | 核心验收 |
| --- | --- | --- |
| 0 契约与安全基础 | CSV 写入规范；薄 schema 与 ID 契约；受管位置 `datasets/`；共享跨进程协调器（md、CLI、检查点同时接入）；`csv` 直接依赖；Glide 原型；旧 DTO 兼容样例 | 两个独立进程并发写入时没有静默覆盖；组合操作不因重入死锁；CSV 与 schema 同批进入检查点；真实 Tauri 中文输入法通过；多行字段、异常引号、编码都不丢值 |
| 1 可编辑 MVP | 新建/导入/发现/打开；展开编辑；字符串单元格与增删行列、粘贴、撤销；自动保存；严格 hash 冲突；提取为 CSV；内联精度保护；最小 CLI 追加 | 没有 ID 的 CSV 可编辑；在视图中改一行不丢隐藏行；两处打开同一 CSV 不互相覆盖；CSV 写入不经过内联类型转换；提取后没有两份可写副本；关窗和失败都不静默丢输入 |
| 2 语义与共享查询 | schema 列类型与枚举；DTO v2（`format`、`where`）；内存执行器 + SQLite 投影；旧表迁移向导 | 同一 CSV 在多篇笔记里各有视图；删除缓存后能完整重建；索引与内存执行结果一致；旧 filter 结果不变；OR 不被压成 AND；迁移报告完整 |
| 3 规模与冲突 | 10 万行 / 50 MB 路径；分页 IPC；按 ID 三方合并；精确记录更新；写回优化 | 达到目标机器的性能预算；大文件不整份复制进 React 状态；改不同行可自动合并，改同一字段的冲突可解释 |
| 4 引用与搜索 | 持久单行引用；可选单元格全文搜索 | 重排后引用仍准确；删行后不跳错行；中文短词可搜 |

阶段 1 的上限先沿用旧实现的 1 万行 / 128 列 / 30 万单元格作为保守起点，阶段 0 实测后再调整。超出编辑能力的文件只读并明示，绝不能截断读取后仍允许保存。

**待本地验证**：Glide 在 WKWebView 中的中文输入法表现（连续拼音、Enter/Tab/Esc、失焦、快速切格）；CSV 解析严格性样例集；GBK/UTF-16/分号分隔等编码与方言识别，低置信度时要用户确认；Excel 覆盖保存、编辑器原子 rename、mtime 不变但内容已变等外部修改场景；替换各阶段崩溃、磁盘满、无权限；大文件全链路的耗时、峰值内存和写门占用时长；备份、导出、同步清单是否漏掉 `datasets/` 和 schema；旧表选项存 ID 还是标签、空值编码、日期格式、筛选操作符的真实情况。

## 9. 待用户决定

1. **数据集放在哪个目录**：新增受管根 `datasets/`（推荐，需改 `MANAGED_VAULT_ROOTS` 和备份清单），还是 Pro 建议的 `assets/datasets/`（免改纳管规则，但与附件语义冲突）。
2. **「新建数据集」是否自动生成一篇说明碎片**：Pro 这样建议，是为了保证数据集在时间线上有入口；代价是多出一条碎片。
3. **BOM**：库内不带 BOM，意味着部分 Excel 双击主文件时中文可能乱码，需要走 Excel 的导入 CSV 或 Shard 的导出。这样理解「Excel 直接可读」是否可以接受？
4. **阶段 0 范围**：跨进程协调器会同时改造 md 的写入链路和 CLI，先于任何 CSV 编辑功能上线。这是正确性的前提，但会让 CSV 功能晚一个阶段才可见。
