# 碎片滚动性能修复

日期：2026-09-10。

## 范围与基线

处理自然向下滚动触发工作台重渲染、关闭的关联弹窗重复计算、瀑布流重复建立尺寸监听的问题。保留现有 Kiln 外观、完整正文、渐进加载、输入框折叠、编辑草稿和选区、阅读锚点与搜索定位。先修复已测得的冗余工作，再根据结果判断大列表是否需要进一步优化。

基线来自 Chromium 开发页面、80 条合成碎片、40 张已挂载卡片；24 次真实鼠标滚轮下滚且未追加卡片时，工作台 render 调用 48 次（开发 StrictMode）、瀑布流测量 48 次、日期格式化 40320 次，出现 24 个超过 50ms 的长任务。相同上滚没有这些额外计算；仅在测试响应中停掉重复折叠信号后，下滚的额外计算也归零。该测量不是原生 Tauri 性能验收。

## 实施计划

| 步骤 | 改动 | 完成标准 |
| --- | --- | --- |
| 1. 隔离折叠状态 | `FragmentsWorkspace` 将自然下滚直接交给 `CaptureBox` 的局部折叠方法，移除 Workbench 递增信号 | 已折叠时不更新状态；重新展开后仍可折叠；保留草稿和选区 |
| 2. 关联弹窗按需计算 | 保留 Dialog 生命周期，将候选索引、搜索和摘要放入实际打开时挂载的内容 | 关闭弹窗不建索引或生成摘要；打开、搜索、确认和焦点恢复正常 |
| 3. 稳定瀑布流监听 | 监听器持续存在；列表身份/顺序、显式定位或布局模式变化时请求测量，尺寸变化由 ResizeObserver 驱动 | 普通重渲染不重建监听；追加、删改、图片增高、宽度变化仍正确排版 |
| 4. 对照与回归 | 性能测试检查事件、重渲染、监听及几何读取；交互测试覆盖折叠、编辑、定位和重排 | 稳定滚动没有无关渲染或测量；必要构建和相关 UI 通过；分别记录浏览器与原生证据 |

## 验收方法

- 用相同合成数据和真实 `mouse.wheel`，对照连续向下、向上，以及输入框首次折叠后的稳定滚动。CI 断言稳定的工作量指标，帧耗时作为环境相关诊断数据。
- 回归展开—折叠—重新展开、草稿/选区保留、程序化搜索定位不折叠 composer、40 条后继续加载、单双列切换、异步高度增长、过滤与返回阅读位置。
- 运行 `pnpm build`、`pnpm test:ui` 的相关用例和 `git diff --check`。原生验证只使用当前构建与当前环境，不能用旧安装版窗口替代。

## 实施与验证结果

上述三项源码修复已完成。另外补全了“输入框仍持有焦点时，点击正文也能重新展开”的交互；折叠不改变正文或选区。

### 同条件性能对照

80 条合成碎片、40 张已挂载卡片、1800 × 900 视口；输入框已折叠，连续 24 次真实滚轮事件使时间线从 1200 滚到 3600，期间没有追加卡片。两次测量的列表高度、输入框高度与 document 滚动位置一致。

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 工作台 render 调用（开发 StrictMode） | 48 | 0 |
| 瀑布流测量 | 48 | 0 |
| 卡片尺寸读取 | 1920 | 0 |
| 日期格式化 | 40320 | 0 |
| 超过 50ms 的长任务 | 24 | 0 |
| RAF 帧间隔 p95 | 83.3ms | 9.2ms |

修后稳定下滚的最大帧间隔为 9.4ms，没有超过 20ms 的慢帧。帧耗时只代表本机这次 Chromium 开发环境采样；CI 使用零无关渲染/测量等稳定指标，避免把机器速度当作功能门禁。

[前后测量摘要](../../tests/evidence/fragments-scroll-performance/comparison.json)。临时诊断通过浏览器响应插桩计数，不修改产品行为；完整原始数据在 `/tmp/shard-fragment-scroll-diagnostic/results.json` 和 `/tmp/shard-fragment-scroll-after/results.json`。

- `pnpm test:ui tests/ui/fragment-masonry.spec.ts`：Chromium 11/11 通过，覆盖默认首页几何、筛选、重排、阅读锚点、异步增高、80 条渐进加载和返回位置。
- `pnpm test:ui tests/ui/shadcn-migration.spec.ts --grep '片段关系层'`：6/6 通过，包含新加的关闭弹窗零候选计算、实际打开搜索、关闭焦点恢复、重开重置和确认关联。

- 独立静态审查未发现新增的陈旧回调、StrictMode 清理、同高重排或过滤返程问题；`git diff --check` 通过。
