# 碎片与资料库分离：第一阶段实施验收

日期：2026-09-10。对应 [产品设计稿](../design/fragments-and-library-separation.md) 的第一阶段“归属闭环”。改动位于当前工作区，保留既有未提交改动；没有提交、推送或发版。

## 已实现的行为

| 场景 | 当前行为 |
| --- | --- |
| 碎片入口 | 默认展示完整公开碎片流，取消最近 5 条限制；每批逐步挂载 40 条。无 inbox 标签的历史碎片仍可见；文档、私密和已删除内容不进入此流。 |
| 碎片筛选与整理 | 筛选从搜索入口按需设置，默认首页没有筛选工具栏；卡片更多菜单进入多选并选中当前卡，保留 AI 整理；选择归零即退出多选。底部选择栏不推动卡片，记录框与时间线分别承担固定输入和局部滚动。 |
| 回顾 | 每日回顾、洞察、随机漫步成为碎片子视图，旧回顾路由兼容映射。 |
| 资料库 | 仅保留文件、图片、资料库回收站与密匣入口，不再展示碎片流、碎片月份和标签树。 |
| 转为文档 | 填写标题、选择目录；保留原对象身份、正文、标签与原记录时间。成功后退出碎片流，在资料库打开正文并聚焦。标题仅决定文档名称，不改写正文。 |
| 转回碎片 | 先保存最新正文，再转换并定位碎片；落盘位置按原创建月份恢复，已有文档编辑器不再写入旧路径。 |
| 整理并保存文档 | 沿用现有 AI 整理后直接保存能力，提交文案明确结果会保存到资料库；来源碎片保留。预览尚未作为本阶段新增功能。 |
| 搜索与引用 | 碎片内搜索限定碎片；全局搜索按当前身份与类型定位。文档内链接、关联、画布引用打开碎片空间；资料库画布只显示碎片标题摘要与打开入口。 |
| 空间恢复 | 恢复碎片筛选和滚动位置、资料库目录/文件选择；同筛选内跳转不清空筛选，跨空间提供返回来源入口。 |
| 回收站 | 碎片与资料库列表、清空范围隔离；搜索已删除碎片可滚动并聚焦，恢复后等待数据刷新再定位。 |
| 图片 | 资料库默认图片只显示受支持公开文档格式引用的图片；仅碎片使用及来源不明的历史附件不混入默认图片列表。文件仍保留在共享附件目录，不因显示策略删除。 |

密匣沿用现有权限、解锁与存储边界。搜索仍使用共享内容索引，不切断碎片和文档之间的关系。

## 保存与失败一致性

- 导航、筛选和转换前排空当前编辑器保存。保存进行中复用同一请求；失败保留原草稿并阻止依赖该保存的操作。
- 转换在后台执行，遵守现有 vault gate 和结构操作 checkpoint 规则。提前规划文件与链接变化，失败回滚。
- 转换返回失败时读取同一对象的当前类型。若已成功，打开实际所属空间；若仍是原类型，才允许重试。
- 状态读取也失败时，正向转换面板只允许“重新核对”；逆向转换暂停旧编辑器写入并提供重新核对。不会把未知结果当作未执行而直接重复转换。
- 目录重名保护与引用更新由底层转换流程处理；原创建时间和身份不因转换重建。

## 2026-09-10：首页极简布局修正

用户否定了常驻的标签、时间、置顶、搜索和多选两排控件；当前已移除整排容器，默认首页恢复输入框与碎片流。筛选通过左侧搜索→筛选碎片→查看碎片进入；仅有活动筛选时出现条件摘要与清除入口。多选放在卡片既有更多菜单内，进入后选中当前卡。

参考 [flomo 官方快捷搜索说明](https://help.flomoapp.com/advance/search.html) 的搜索内按需筛选模式，没有替换 Shard 的字体和视觉规范。原文确认桌面左上搜索入口及自定义时间、标签等条件入口；本次不声称复刻其全部筛选能力。

本轮构建与整理专项 6 项、首页/筛选专项 7 项通过。桌面实测 composer 底部 223px、首卡顶部 239px，默认间距 16px；活动摘要占 36px，清除后恢复原位。640×520 下弹层、下拉菜单均未越界，键盘选择与取消后焦点恢复通过。
