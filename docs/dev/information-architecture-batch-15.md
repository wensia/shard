# 树只管位置，宫格只管内容（IA 重整第十五批 M）

## Context

用户指出：**「左侧边的文件树和文件管理宫格视图有冲突，需要更加优雅的方式」**（截图里第二栏与第三栏列的是同一批 5 个文件）。

## 根因：两种模型被混在一起

| 模型 | 侧栏职责 | 主区域职责 |
| --- | --- | --- |
| Obsidian 式 | 树展开到**文件**，点文件直接打开 | 无文件管理视图 |
| Finder 式 | 侧栏只管**位置**（目录/收藏） | 当前位置的文件列表/图标 |

第十二批给第三栏加了目录浏览（Finder 式），却没有相应收敛第二栏的职责（仍是 Obsidian 式），于是在任何目录下**同一批文件都出现两遍**。

## 用户裁决

**采用 Finder 模型**：树只显示目录，文件只在第三栏出现。零重复，心智最清晰。已知代价：树里不能直接点文件了，打开得经第三栏或 ⌘K 搜索。

## 本批最大的风险：操作能力会随文件一起消失

文件的操作菜单目前**全部挂在树上**（`library-shell.tsx:1617` 附近的 `DropdownMenu`）：重命名、移动到…、删除、转为碎片、移入密匣。

而第三栏的 `directory-view.tsx` **完全没有操作入口**（零 `DropdownMenu` / `onRename` / `onDelete`）。

**文件一旦从树里移除，这些能力就全没了。** 因此 T15.2 与 T15.1 必须同批完成，不可拆分。

## 核心裁决

| # | 裁决 |
| --- | --- |
| D1 | 树只渲染 `kind === "directory"` 的条目，外加既有特殊入口（碎片流 / 图片 / 密匣挂载点）。md / csv / 导图**一律不进树**。 |
| D2 | 文件的全部操作迁到第三栏，**列表与宫格都要有**：重命名、移动到…、删除、转为碎片、移入密匣（后两项仍仅 markdown）。**复用树上既有的菜单组件与回调，不新写一套逻辑**。 |
| D3 | **目录的操作留在树上**（目录仍在树里），同时第三栏的目录条目也提供同一套菜单——两处入口指向同一批回调。 |
| D4 | 新建笔记 / 新建目录按钮**留在第二栏头部**，语义不变（作用于当前选中目录）。不迁移，避免本批范围膨胀。 |
| D5 | 宫格格子的菜单触发器**放右上角、hover/focus 时才显形**，不能常驻遮挡缩略图；列表行的触发器放行尾，与既有树行一致。 |
| D6 | 树上目录的展开/折叠与选中双动作（第十二批 D1）**保持不变**——点目录仍是既展开又在第三栏显示内容。 |

## 非目标

- 不动碎片流 / 图片 / 密匣三个特殊入口的位置与行为。
- 不迁移新建按钮（D4）。
- 不做拖拽移动、不做多选批量操作。
- 不改第三栏列表/宫格的既有布局与缩略图实现（第十二、十四批）。
- 不给树加"显示文件"开关（那是妥协，不是解法）。

## T15.1 树只渲染目录

**文件**：`src/workspace/library-shell.tsx`

**做什么**

1. 渲染树条目的 `entries.map`（约 `:1523`）前先过滤：只保留 `kind === "directory"`。
2. 目录的展开/折叠、双动作选中（第十二批 D1）、`data-selected` 全部保持不变。
3. 目录为空（无子目录）时不渲染展开箭头，与现状一致。
4. 碎片流 / 图片 / 密匣三个特殊节点**不受影响**。
5. `directories`（移动目标列表）的计算不变——它本来就只收集目录。

**验收**：`pnpm build` 通过；树里不再出现任何文件条目

**禁止**：不要给树加过滤开关；不要动特殊入口

---

## T15.2 文件操作迁到第三栏

**文件**：`src/components/shard/directory-view.tsx`、`src/components/shard/asset-grid.tsx`、`src/workspace/library-shell.tsx`

**做什么**

1. `DirectoryView` 新增操作回调 props，签名与树上现有的保持一致：`onRename` / `onMove` / `onDelete` / `onConvertToFragment` / `onMoveToLockbox`，外加移动目标目录列表 `destinations`。
2. **列表形态**：每行行尾加「…」触发器 + `DropdownMenu`，菜单项与树上完全一致（重命名 / 移动到… / 删除；markdown 额外有转为碎片 / 移入密匣）。
3. **宫格形态**：格子右上角加「…」触发器，`opacity: 0` 常态、`:hover` 与 `:focus-within` 时显形（D5），菜单内容同上。
4. **目录条目**同样提供菜单（D3），菜单项为重命名 / 移动到… / 删除（无转碎片/移入密匣）。
5. `library-shell` 把既有的回调**原样透传**下去——那些函数（`renameLibraryEntry` / `moveLibraryEntry` / `deleteLibraryEntry` / `onConvertToFragment` / `onMoveToLockbox`）已经存在，**不要新写**。
6. 重命名的行内输入态：复用树上既有的 `renaming` 状态机与 `onRenameSubmit`，不要为第三栏另造一套。
7. 删除非空目录的阻止逻辑（`:724` 那条 toast）同样生效。

**验收**：`pnpm build` 通过；列表与宫格里都能完成重命名/移动/删除；markdown 条目额外有转碎片与移入密匣

**禁止**：不要新写任何 mutation 逻辑；不要让菜单常驻遮挡缩略图；不要给 csv/导图加「转为碎片」「移入密匣」

## T15.3 测试

**做什么**

1. **Playwright**：
   - 树里**不再出现** md / csv / 导图条目（`toHaveCount(0)`），但目录仍在
   - 碎片流 / 图片 / 密匣三个入口不受影响（回归保护）
   - 列表视图里可对文件重命名、移动到子目录、删除
   - 宫格视图里可对文件重命名、移动、删除
   - markdown 条目在第三栏有「转为碎片」「移入密匣」，导图/csv 没有
   - 目录条目在第三栏有菜单，且无「转为碎片」
   - 删除非空目录仍被阻止
   - 点目录仍是双动作（展开树 + 第三栏显示内容，第十二批 D6 回归保护）
2. 既有用例中依赖「点树里的文件」的断言需要改走第三栏——**逐条修正，不要删除用例**。
3. 断言用 `exact` 或区域限定。

**验收命令**（三条全绿）：

```bash
cargo test --manifest-path src-tauri/Cargo.toml
pnpm build && pnpm test:unit
pnpm test:ui
```

**禁止**：不要为了让用例通过而删除既有断言；既有用例数量只能增不能减（改写可以）

## 主要风险

- **R1 · 操作能力静默丢失**：本批最大风险。文件从树里移除后，若第三栏菜单有任何一项没接上，用户就永久失去该能力且不会立刻发现。验收时必须逐项核对五个操作在两种视图下都可用。
- **R2 · 既有用例大面积依赖树里的文件**：`library-tree.spec.ts` 里大量用例点的是树中的 `xxx.md`。这些要改走第三栏，工作量集中在测试改写，**不是删用例**。
- **R3 · 宫格菜单遮挡缩略图**：触发器必须 hover/focus 才显形（D5），否则每个格子右上角常驻一个「…」会毁掉刚做好的缩略图观感。
- **R4 · 打开文件多一步**：这是用户已接受的代价。若后续觉得不便，补救方向是 ⌘K 搜索或"最近文件"，**不是把文件放回树里**。
