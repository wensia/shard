# 回收站取代归档（IA 重整第十六批 N）

## Context

用户定调：**「归档应该改名为回收站，架构上也应该改，回收站不限制任何类型的文件」**，并明确选择**回收站取代归档**（归档概念消失）+ **vault 顶层 `.trash/` 目录**存储。

## 查证：现状与两个连带结论

**删除是永久的**：`delete_library_entry`（`lib.rs:3033-3035`）直接 `fs::remove_file` / `fs::remove_dir`，没有任何中转。全仓库唯一提到"回收站"的是密匣的一句提示文案（`workbench-shell.tsx:1963`）。所以本批不是改名，是**新增软删除机制**。

**归档仍是目录**：第三至五批（归档正交化，改 frontmatter）**尚未实施**——`archive/` 仍在 `MANAGED_VAULT_ROOTS`（`lib.rs:48`），`archived` 仍从路径前缀派生（`:1088`），列表仍扫 `archive/`（`:1302`）。

由此得出两个结论：

1. **演化路径是通的**：归档本来就是目录，回收站也需要目录（图片等二进制无处写字段），可以直接从 `archive/` 演化到 `.trash/`。
2. **第三至五批应当废弃**：它们的目标是「归档改 frontmatter 字段」，理由是归档要扩展到 `notes/` 且避免目录笛卡尔积。但归档概念既然消失，回收站是**删除的终态**而非与位置正交的状态，用目录才是对的。那三批连同「双读 / 幂等迁移 / 单读」的全部设计一并作废。

## 核心裁决

| # | 裁决 |
| --- | --- |
| D1 | **回收站取代归档**：`Fragment.archived` 语义改为「在回收站中」；树上「归档」节点改为「回收站」，图标改 `Trash2Icon`。归档作为独立概念消失。 |
| D2 | **`.trash/` 保留原相对路径结构**：`notes/项目/笔记.md` → `.trash/notes/项目/笔记.md`。恢复时直接搬回，无需额外索引。同路径冲突时加时间戳后缀。 |
| D3 | **删除即入回收站，不再永久删除**：`delete_library_entry` 与碎片的删除路径统一改为移入 `.trash/`。永久删除只发生在回收站内的「彻底删除」与「清空回收站」。 |
| D4 | **不限文件类型**：md / csv / 导图 / 图片 / 碎片一律可入回收站。目录删除时整棵搬入。 |
| D5 | **回收站不做自动清理**：只有用户手动「彻底删除」或「清空回收站」才真正删文件。单人本地工具，静默删数据的风险远大于省下的磁盘。 |
| D6 | **旧 `archive/` 一次性迁移到 `.trash/`**：现有 29 条归档碎片视为「已移出视线」，与回收站语义最接近。因 D5 不会被自动清理，用户可随时恢复。迁移幂等。 |
| D7 | **密匣的删除仍留在密匣内**：`lockbox/` 内容不进明文 `.trash/`（否则加密内容会以明文落到回收站）。密匣内删除维持现有行为，本批不改。 |

## 非目标

- 不做定时清理、不做容量上限、不做「30 天后自动删除」（D5）。
- 不改密匣的删除行为（D7）。
- 不做回收站内的搜索与筛选。
- 不实施第三至五批（已废弃，见上）。

## T16.1 Rust：`.trash/` 目录与移入逻辑

**文件**：`src-tauri/src/lib.rs`

**做什么**

1. `MANAGED_VAULT_ROOTS`（`:48`）加入 `.trash`；`ensure_vault_dirs` 不必预创建（移入时 `create_dir_all`）。
2. 新增 `move_to_trash_in_vault(vault, rel_path)`：把任意 vault 内相对路径（文件或目录）搬到 `.trash/<原相对路径>`，父目录自动创建，同路径已存在时在文件名后加 `-<时间戳>`。
3. 新增 `restore_from_trash_in_vault(vault, trash_rel_path)`：搬回原位置（去掉 `.trash/` 前缀），目标已存在时同样加后缀，**不覆盖**。
4. 新增 `purge_from_trash_in_vault` / `empty_trash_in_vault`：真正 `fs::remove_*`，仅作用于 `.trash/` 内路径，**必须校验路径确实在 `.trash/` 下**（防目录穿越）。
5. `delete_library_entry`（`:3033`）改为调用 `move_to_trash_in_vault`，不再直接删除。
6. 碎片的删除路径同样改走回收站。
7. 三个新 command：`restore_from_trash` / `purge_from_trash` / `empty_trash`；`list_fragments` 收集范围把 `archive/` 换成 `.trash/`。

**验收**：`cargo test` 通过；新增单测见 T16.5

**禁止**：不要让 purge/empty 接受 `.trash/` 之外的路径；不要碰 `lockbox/` 的删除（D7）

## T16.2 Rust：`archive/` 一次性迁移

**做什么**

1. 迁移函数：`archive/**` 全部搬到 `.trash/`，保留相对结构（`archive/2026/08/x.md` → `.trash/fragments/2026/08/x.md`，即还原它原本在 `fragments/` 下的位置）。
2. **幂等**：搬完源文件消失，二次扫描自然跳过；`archive/` 已空或不存在时直接返回。
3. 走 `checkpoint_before_structural_locked`，清理空目录。
4. 单文件失败跳过并保留，不中断整体。
5. 与既有的 T6 遗留笔记迁移互不干扰（前者只碰 `archive/`，后者只碰 `fragments/`）。
6. 迁移后 `archive/` 从 `MANAGED_VAULT_ROOTS` 移除。

**验收**：`cargo test` 通过；幂等性单测

**禁止**：不要在迁移中改写文件内容

## 主要风险

- **R1 · 删除语义变更是破坏性的**：用户此前的「删除」是永久的，此后变成软删除。磁盘占用会增长（D5 不自动清理）。需在清空对话框里说明「此操作不可恢复」。
- **R2 · 目录穿越**：purge / empty 直接 `fs::remove_*`，**必须**校验路径在 `.trash/` 内。这是本批唯一有数据毁灭风险的地方。
- **R3 · 恢复冲突**：原位置已被新文件占据时不能覆盖，必须加后缀。
- **R4 · `.trash/` 进 Git**：回收站内容会被 Git 追踪，删除大文件后仓库不会变小。可接受（本就是 local-first vault），但要在提交信息里记录。
